# SAGA 웹 모바일 3D 게임 무료 에셋 검색 및 적용 지시서

## 0. 프로젝트 전제

현재 프로젝트는 **HTML + CSS + JavaScript 기반 웹 모바일 게임**이다.

기존 게임 구조와 기능을 최대한 유지하면서 무료 고품질 게임 에셋을 도입하여 그래픽 품질을 크게 개선한다.

주요 실행 환경:

- iPhone Safari
- Android Chrome
- 모바일 웹 브라우저
- PC 브라우저

3D가 필요한 경우 기존 웹 기술과 호환되는 WebGL 기반 3D 기술을 사용한다.

---

# 1. 가장 중요한 목표

현재 게임의 가장 큰 문제는 단순한 그래픽과 부족한 환경 디테일이다.

따라서 다음을 목표로 한다.

### 기존

- 단순한 도형
- 단순한 배경
- 부족한 지형
- 반복적인 오브젝트
- 저품질 캐릭터
- 게임 화면이 비어 보임

### 개선

- 고품질 3D 캐릭터
- 다양한 몬스터
- 자연스러운 지형
- 나무/바위/풀/꽃
- 건물
- 마을
- 던전
- 장식물
- 다양한 환경 효과
- 고품질 UI
- 자연스러운 조명
- 깊이감 있는 맵

단순히 에셋 숫자를 늘리지 말고 **하나의 완성된 게임 세계처럼 보이도록 구성한다.**

# 4. 라이선스 규칙

무료라는 이유만으로 사용하지 않는다.

반드시 다음을 확인한다.

- 상업적 이용 가능 여부
- 수정 가능 여부
- 재배포 조건
- 출처 표기 필요 여부
- 라이선스 종류

가능하면 **CC0를 최우선**으로 한다.

라이선스가 불명확한 에셋은 사용하지 않는다.

---

# 5. 웹 모바일용 파일 형식

다음 형식을 우선한다.

## 3D

1. GLB
2. GLTF

웹에서 불필요하게 OBJ/FBX 등을 직접 사용하는 구조를 만들지 않는다.

## 텍스처

1. WebP
2. 압축된 PNG
3. 필요한 경우 JPEG

가능하면 WebP를 우선한다.

---

# 6. 모바일 최적화

매우 중요하다.

PC 게임용 에셋을 그대로 가져와서는 안 된다.

다음 기준을 적용한다.

### 3D 모델

- 저~중간 폴리곤
- 필요하지 않은 디테일 제거
- LOD 고려
- 작은 오브젝트는 단순화
- 동일 모델 재사용
- Instancing 적극 활용

### 텍스처

기본적으로:

- 작은 오브젝트: 256~512px
- 일반 오브젝트: 512~1024px
- 주요 캐릭터: 1024~2048px

모바일에서 반드시 필요한 경우가 아니면 4K 텍스처를 사용하지 않는다.

---

# 7. 로딩 최적화

게임 시작 시 모든 에셋을 한꺼번에 다운로드하지 않는다.

필요한 에셋만 로딩한다.

예:

```text
초기 로딩
↓
메인 화면
↓
현재 지역 에셋 로딩
↓
플레이
↓
다음 지역 이동
↓
다음 지역 에셋 로딩
```

가능하면:

- lazy loading
- dynamic import
- asset caching
- browser cache
- 압축
- preload 최소화

를 사용한다.

# 9. 그래픽 스타일

목표 스타일:

**Stylized Realistic 3D RPG**

너무 단순한 로우폴리 스타일만 사용하지 않는다.

다음 요소를 조합한다.

- 현실적인 재질
- 자연스러운 조명
- 적당한 디테일
- PBR
- 그림자
- 환경 효과
- 안개
- 파티클
- 물 효과
- 자연스러운 색감

단, 모바일 브라우저 성능을 우선한다.

---

# 10. 에셋 스타일 통일

가장 중요한 부분이다.

서로 다른 스타일의 에셋을 무작정 섞지 않는다.

예:

```text
현실적인 캐릭터
+
만화풍 건물
+
극도로 단순한 나무
+
픽셀아트 몬스터
```

같은 조합을 피한다.

가능하면 같은 제작자 또는 같은 에셋 팩의 에셋을 여러 개 사용한다.

---

# 11. 맵의 밀도 개선

현재 맵이 비어 보이지 않도록 한다.

플레이어 주변에 자연스럽게 다음을 배치한다.

```text
나무
바위
풀
꽃
덤불
통나무
상자
표지판
횃불
건물
NPC
몬스터
장식물
```

단순 랜덤 배치가 아니라 자연스러운 군집을 만든다.

예:

```text
큰 나무
 ├─ 작은 나무
 ├─ 풀
 ├─ 꽃
 └─ 바위
```

이런 방식으로 환경을 구성한다.

# 14. 웹 3D 엔진

현재 프로젝트 구조를 먼저 분석한다.

이미 사용 중인 3D 라이브러리가 있다면 그것을 우선 활용한다.

없다면 프로젝트 규모에 맞춰:

- Three.js
- Babylon.js

등을 검토한다.

단, 기존 게임 기능을 불필요하게 전부 다시 작성하지 않는다.

**기존 시스템을 최대한 유지하면서 필요한 부분부터 3D화한다.**

# 17. Claude Code 토큰 절약

매우 중요하다.

불필요한 웹 검색과 파일 분석을 반복하지 않는다.

### 검색 방식

한 번에 모든 에셋을 찾지 않는다.

다음 순서로 진행한다.

```text
1. 캐릭터
2. 몬스터
3. 환경
4. 건물
5. 던전
6. UI
```

각 카테고리에서 우수 후보를 최대 5~10개만 선정한다.

이미 검토한 에셋은 다시 검색하지 않는다.

---

# 18. 최종 에셋 선정

후보를 다음 기준으로 평가한다.

```text
품질              30%
웹 호환성         20%
모바일 성능       20%
스타일 통일성     15%
라이선스 안정성   15%
```

높은 점수의 에셋만 실제 프로젝트에 적용한다.

---

# 19. 절대 금지

다음 행동을 하지 않는다.

- 라이선스 불명확한 에셋 사용
- 무단으로 유료 에셋 사용
- 대용량 4K 텍스처 남발
- 수십 MB짜리 모델을 모바일에 무조건 적용
- 모든 에셋을 초기 로딩
- 서로 다른 스타일의 에셋 무작위 혼합
- 기존 기능을 이유 없이 전부 재작성
- 사용하지 않는 라이브러리 추가
- 불필요한 대규모 리팩터링

- package.json

- JavaScript 구조
- 현재 렌더링 방식
- 현재 3D 구현 여부

- 현재 성능 문제

분석 결과를 장황하게 출력하지 말고 핵심 문제와 해결 방법만 정리한다.

# 22. 최종 목표

결과물은 단순한 웹 게임처럼 보이지 않아야 한다.

모바일 브라우저에서 실행했을 때:

**"3D 모바일 RPG 게임을 실행하고 있다"**

라는 느낌이 들도록 만든다.

특히 다음 5가지를 최우선으로 개선한다.

1. 캐릭터 품질
2. 환경/지형 밀도
3. 조명과 재질
4. 맵의 다양성
5. 모바일 성능

무료 에셋을 사용하되 최종 결과물은 무료 에셋을 단순히 나열한 느낌이 나지 않도록 구성한다.
