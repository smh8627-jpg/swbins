# saga-web 맵 편집기

판마다 다른 "지도 데이터"를 브라우저에서 칠하고 옮기는 로컬 전용 도구. 지도 모양이 판마다 달라서
**어댑터**(`adapters/*.js`) 하나가 데이터 파일 한 가지를 맡고, 화면도 셋이다(위 줄에서 오간다).

```
run-map-editor.bat        → http://127.0.0.1:8800/   (끄기: 창 닫기 또는 Ctrl+C)
```

| 화면 | 어댑터 | 파일 · 고치는 것 | 지금 대상 |
|---|---|---|---|
| 글자 지도 `map.html` | `land` | `js/land.js` 땅의 `map`(글자 줄)·`places`(명소) | 사가고 `hebei`(21×21칸·한 칸 48m) |
| 성 지도 `city.html` | `city` | `js/data-city.js` 성의 `x`·`y`·`land` 와 `LINKS`(길) | 사가국지 135성 |
| 사냥터 `side.html` | `side` | `js/data-side.js` `STAGES` 한 곳의 `width` · `plats`·`ropes`·`portals`·`npcs`·`gathers` | 사가스토리 11곳(마을 5·사냥터 6) |

판 폴더에 그 파일이 생기면 저절로 목록에 뜬다(`/api/kinds`).

## 세 어댑터 공통

- **검사는 게임 데이터 그대로**: 고친 파일을 vm 에서 실행해 게임이 보는 그 객체(`DG.land`·`DG.cityData`·`DG.sideData`)로 본다.
  고칠 때마다 오른쪽에 바로 뜬다. 게임에 검사 함수가 있으면 그것을 부르고(`land.validate()` 등), 없으면 그 판 `_test.html` 진단과 같은 조건을
  어댑터가 본다 — 게임 파일은 안 고친다.
- **저장은 바뀐 구간만** 바꿔 쓴다(주석·줄 맞춤·다른 값 그대로). **안 바꾸고 저장하면 파일을 아예 안 쓴다**(바이트 동일, sw.js 도 안 올림).
- 막는 것: 그새 파일이 바뀜(md5 — 다른 세션·편집기) · 파일 구문 오류 · 어댑터 검사 오류 · 표시 글자 실명(`../content-editor/realname.js`).
  저장하면 그 판 `sw.js` VERSION 을 서버 실행당 한 번 올린다.
- 되돌리기 Ctrl+Z. git 은 건드리지 않는다.
- 이름·설명·수치 같은 **글자 칸은 여기서 안 고친다**(콘텐츠 편집기 `../content-editor/` 판별 표 몫). 그래서 성 지도·사냥터에는 실명 가드에 걸 글자가 없다.

## 글자 지도(사가고)

- **도구**: 칠하기(끌기) · 채우기 · 스포이트 · 명소 옮기기 · 오른쪽/아래로 열·줄 늘리고 줄이기.
  왼쪽·위로는 안 늘린다(격자 원점 `ox/oy` 와 명소 좌표가 한꺼번에 밀린다). 흰 테두리 칸 = 격자 (0,0), 게임 시작 자리.
- **범례**는 그 땅의 `legend` 를 그대로 쓴다(새 글자·지형은 `land.js` 에서 코드로 먼저 정의).
- 검사는 그 판의 `validate()`·`roadIslands()`·`tally()`. 길이 끊긴 것(`roadIslands() ≠ 1`)은 막지 않고 경고만 한다.
- 게임 `_test.html` 땅 진단은 지형 갈래 개수·숨은 곳 넷 같은 **내용 조건**도 본다 — 편집기는 형식만 막으니, 크게 고쳤으면 진단을 한 번 돌린다.
- `tools/scene-layout/layout.mjs` 가 `server.js` 의 `evalLand` 를 가져다 쓴다(이름 그대로 내보낸다).

## 성 지도(사가국지)

- **도구**: 옮기기(끌기, 정수 칸에 붙는다) · 길 잇기·끊기(두 성을 차례로 누른다, 이어졌으면 끊는다) · 지형 칠하기. 주(州) 골라 보기·성 찾기·휠 확대.
  파란 점선은 물길(양쪽 다 `river`) — 지형 한 글자로 물길이 따라 움직이는 게임 규칙 그대로 보인다.
- **막는 것**: 없는 성을 가리키는 길(`_dropped`) · 길 없는 성 · 낙양에서 못 닿는 성 · 모르는 지형 · `ui-rtk.js` `MAP_VB`(지도 전체 범위) 밖의 성
  (범위를 넓히려면 `ui-rtk.js` 두 곳을 먼저 고친다 — 그 파일 주석). 같은 길이 두 번 적힌 것은 경고.
- 저장: 성 객체의 `x`·`y`·`land` 값 글자만 바꾼다. 길은 지운 쌍만 `LINKS` 에서 빼고(빈 줄·쉼표 정리), 더한 쌍은 배열 끝에 한 줄로 붙인다.
  길의 순서·방향만 달라진 것은 바뀐 게 아니다.
- 성을 새로 만들거나 없애지는 않는다(이름·내정 값·수비 무장이 딸려 있어 `data-city.js`·`data-force.js` 를 손으로).

## 사냥터(사가스토리)

- **도구**: 고르기·끌기 · 발판/줄/문/사람/채집 더하기 · 고른 것 지우기(Delete) · 폭. 10 단위로 붙기(끌 수 있음).
  발판 오른쪽 끝(흰 손잡이)을 끌면 폭, 줄은 위·아래 끝을 끌면 그 끝만(위 끝은 가까운 발판 윗면에 붙는다), 가운데를 끌면 통째로.
  흰 점선은 들어올 때 서는 자리(왼쪽 130 · 오른쪽 폭−160, `side.js` 그대로).
- **막는 것**: 줄 수 < 발판 수 · 문 없음(둘 다 `_test.html` "줄"·"문" 진단) · 없는 사냥터로 가는 문 · 폭 밖·바닥 아래 발판 ·
  위 ≥ 아래인 줄 · `rope`/`ladder` 가 아닌 줄 · `NPC_TALK`·`GATHERS` 에 없는 사람·채집 갈래 · 폭 400 미만.
  **경고만**: 되돌아오는 문이 없는 문(양쪽 사냥터를 같이 고칠 때 한쪽씩 저장하게), 어느 발판 윗면에도 안 닿는 줄 위 끝.
- 저장: 그 사냥터 객체에서 **바뀐 칸만** 다시 쓴다(100열에서 줄바꿈, `[` 다음 열에 맞춤). 없던 칸(싸움터에 `npcs` 등)은 `portals` 뒤에 붙인다.
  한 파일에 사냥터가 열한 곳이라, 저장하면 목록의 다른 사냥터 해시도 같이 새로 맞춘다(이어 고쳐도 충돌 안 남).
- `floor`(바닥 높이)는 안 고친다(지금 열한 곳 모두 560).

## 못 넣은 판

- **사가의숲** — 마을(30×20 타일)·숲 고리·강·만남 격자가 전부 세이브 씨앗 해시로 **코드가 절차 생성**한다(`village.js`·`grid.js`·`terrain.js`).
  고정 지도 데이터가 없으니 편집할 표가 없다. 넣으려면 먼저 게임 쪽에 "손으로 정한 배치" 층을 만들어야 한다(설계 결정 — 사용자 몫).
- **사가블로** — 던전은 로그라이크라 층마다 절차 생성(`dungeon.js`, 데이터는 층 테마·방 종류 표뿐). 마을 배치(`town.js` `TOWNS`·`MARKS`·`DECOR_*`)는
  있지만 로직 파일 안에 섞여 있고, 방 크기 배율(`DESK_SCALE`)·세계 앵커 지터·길 잇기(`connectAndRoadTowns`)가 좌표를 다시 계산해
  편집기에서 본 자리와 게임 자리가 어긋난다. 데이터 파일로 떼어 내는 것이 먼저다.

## 시험 요령

`SAGA_WEB_ROOT=<복사본의 saga-web 자리> node server.js` 로 켜면 그 복사본을 고친다(실제 판 파일을 안 건드리고 저장 경로까지 시험).
서버를 띄워 시험했으면 PID 로만 끈다(`taskkill //PID <n>`, `//IM node.exe` 금지).
