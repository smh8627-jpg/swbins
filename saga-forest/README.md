## 앞으로 — 3D 로 옮긴다 (`PLAN.md`)

이 폴더의 **`PLAN.md`** 가 앞으로의 방향이다. 이 README 의 나머지는 **지금까지 만든 것**이니,
손대기 전에 둘을 같이 본다.

가는 곳은 **3D 오픈 필드 생활 게임** 이다 — 지금의 수집·생활 재미를 그대로 두고, 땅을 넓혀
바이옴이 갈리는 자연 속에서 주민과 지내고 탐험·채집·낚시·건축을 한다.

**Phase 1~15** 로 잘라 간다 — 현재 분석 → 3D 렌더링 추가 → 카메라 → 플레이어 →
넓은 월드 → **chunk** → 바이옴 → 나무·풀·돌 → GLB → 주민 모델 → 집·마을 →
채집 → 낚시 → 시간·날씨 → 모바일.

지키는 선: **전체 재작성 금지 · 기존 UI 임의 제거 금지 · 데이터 구조를 확인하지 않고
새 구조 강제 금지 · placeholder 대량 생성 금지 · 한 번에 모든 파일 수정 금지.**
움직이는 것을 이유 없이 리팩터링하지 않는다.

## 가입해서 저장 (account.js)

첫 실행 때 **이름**을 물어보고, 그 이름으로 진행이 저장된다. 서버는 없다 —
이 브라우저 안에서만 도는 가입이고 비밀번호도 없다.

```
세이브 키   <게임>/save/<프로필id>      ← account.js 가 정해 준다
프로필 목록 <게임>/save/accounts
옛 세이브   <게임>/save/v1             ← 첫 가입 때 '이어받기' 로 옮긴다
```

- 게임 코드는 `game.js` 의 `boot()` 에서 **`DG.account.gate(start)`** 한 줄만 부른다.
  gate 가 프로필을 정해 `core.setSaveKey()` 를 부른 뒤 게임을 켠다
- 상단 **👤** 는 account.js 가 직접 끼워 넣는다 (index.html 을 고칠 필요가 없다).
  이름 바꾸기 · 다른 이름으로 새 판 · 삭제
- 이름은 **게임마다 따로**다 (다섯 프로젝트가 별개이므로)
- 자가진단은 `window.DG_NO_ACCOUNT = true` 로 가입 화면을 건너뛰고 `…/save/test` 를 쓴다

## 자가진단

```
chrome --headless=new --disable-gpu --virtual-time-budget=45000 --dump-dom   http://127.0.0.1:PORT/_test.html        → RESULT n/n
```

**무작위는 씨앗으로 고정돼 있다.** `_test.html` 이 게임 스크립트를 불러오기 **전에**
`Math.random` 을 mulberry32(씨앗 20260824)로 갈아 둔다. 그래서 자동 순행을 몇 분치
굴려 보는 항목도 **매번 같은 수치**가 나온다 — 전에는 그 항목들이 드물게 실패했다
(같은 코드로 24/25 → 25/25). 게임 코드는 손대지 않았으니 실제 플레이는 그대로 무작위다.

세 번 돌려 결과가 **한 줄도 다르지 않은지**로 확인한다. 시각 기반 값(프로필 id 등)은
결과 문구에 넣지 않는다 — 넣으면 매번 달라져서 "무엇이 바뀌었나" 를 눈으로 못 쫓는다.

## 손볼 때

- `core.hash2` 는 **부호 없는 시프트**로 고쳐 뒀다(옛 식은 0~0.5 만 돌려줘서, 문턱값을
  0.9 로 잡으면 아무 것도 생기지 않았다). `deungyong-go` 에는 아직 옛 식이 남아 있다
- 파일을 늘리거나 고쳤으면 **`sw.js` 의 VERSION 도 같이 올릴 것.** 안 올리면 브라우저가
  옛 파일을 물고 있어 한 화면에 세대가 섞인다(그래서 실제로 죽은 적 있다)
- 자동 설정(`save.auto`)은 `auto.js` 의 `st()` 가 **빠진 칸을 채워 준다**
- **집 안과 마을은 투영이 다르다.** 마을은 구면(`project`), 방은 평평한 3/4(`projIn`).
  탭 좌표도 `V.indoors()` 로 갈라 되짚는다 — 한쪽 식으로 되돌리면 엉뚱한 칸을 짚는다
- **벌레는 `village.js` 가 아니라 `bug.js` 가 굴린다.** `village.update()` 가 한 줄로 부르고,
  집 안이면 그 줄에 닿기 전에 돌아간다
- **같은 파일 안에서 부르는 함수는 밖에서 갈아 끼워도 안 먹는다.** 진단이 손봐야 하는
  자리(`turnip.marketOpen` · `town.starNow`)는 **구멍을 따로 뚫어 둔다**
  (`_setOpen` · `_setStar` — `_spawnAt`·`_start`·`_put` 과 같은 결이다).
  `VD.season` 처럼 **다른 파일이 부르는** 것만 밖에서 갈아 끼울 수 있다
- **자가진단은 게임 루프를 켜지 않는다**(`DG_NO_LOOP`). 헤드리스에서 프레임 수는
  실행마다 다르고, 그 프레임이 주민을 움직이고 벌레를 내보내므로 항목마다 딛는 자리가
  흔들린다. 진단은 필요한 만큼 `update(dt)` 를 직접 굴린다
- **자동은 도구가 없어 못 하는 것을 목표로 삼지 않는다.** 삽 없이 갈라진 자리로 걸어가
  아무것도 못 하고 다시 그리로 가는 되돌이에 빠진 적이 있다(`auto.js` 의 `freshProp`)
- **프레임마다 도는 것은 공용 `Math.random` 을 먹지 않는다.** `bug.js` 와 `folk.js` 는
  **제 난수를 따로 둔다**(마을 씨앗 ⊕ 날짜로 씨를 뿌린다). 헤드리스에서 프레임 수는
  실행마다 다르므로, 여기서 공용 흐름을 먹으면 씨앗을 고정해 둔 자가진단이 실행마다
  다른 수를 뽑는다 — 실제로 한 번 그렇게 깨졌다. `_test.html` 의
  **'프레임마다 도는 것은 공용 난수를 먹지 않는다'** 항목이 그 못이다
- **`raw().props` 는 살아 있는 배열이다.** 스냅샷의 칸을 갈아 끼우는 것으로는 마을에서
  빠지지 않는다 — 진단에서 그렇게 했다가 다음 항목이 엉뚱한 사물을 짚었다(`dropProp` 참조)
- **이사·편지는 `rollDay()` 에서만** 굴린다. 부탁을 지우기 **전에** 어제 누구를 도왔는지
  먼저 챙긴다 — 감사장이 거기서 나온다
- 마을 좌표 ↔ 화면 좌표는 **반드시 `project`/`unproject` 를 거친다.** 탭한 자리를
  `sx + cam.x` 로 되돌리던 옛 식은 구면 투영에서 엉뚱한 칸을 짚는다
- 헤드리스 크롬(`--screenshot`/`--dump-dom`)에서는 `requestAnimationFrame` 이 거의 돌지
  않는다. 움직임은 스크린샷으로 판정할 수 없으니 `_test.html` 처럼 `update(dt)` 를
  직접 굴려서 본다

## 그림 — 원작의 투영을 그대로 (2026-08-26)

원작이 "동물의숲처럼" 보이는 이유는 귀여운 그림체가 아니라 **투영**에 있다.
`village-view.js` 의 심장은 `project()` / `unproject()` 이고, 나머지는 전부
"투영된 자리에 무엇을 그리나" 일 뿐이다.

1. **마을이 원통에 감겨 있다** — 앞으로 갈수록 땅이 휘어 오르다가 지평선(마루)에서
   넘어가 사라진다. **마을 전체를 한눈에 볼 수 없다**. 이게 제일 큰 차이다
2. **좌우 가장자리가 아래로 처진다** (`BEND`) — 공 위에 서 있는 느낌
3. **카메라가 사람을 늘 한가운데 둔다** — 옛 코드처럼 마을 안으로 가두지 않는다.
   마을 밖은 `tileAt` 이 물을 돌려주므로 저절로 **섬**이 된다
4. **비스듬히 내려다본다** (`TILT`) — 곧게 내려다보는 탑다운이 아니다

상수는 넷이다 — `R`(구면 반지름) · `TILT`(내려다보는 각) · `BEND`(좌우 처짐) ·
`ZOOM`(화면 크기 보정, `resize()` 가 정한다). `ZOOM` 이 없으면 작은 화면에서
지평선이 화면 위로 밀려 나간다.

그 위에 얹힌 것:

- **사물은 이모지가 아니라 도형이다** — 나무는 겹친 원 여섯으로 수관을 만들고,
  수관 색이 계절을 탄다(봄 벚빛 · 여름 초록 · 가을 주황 · 겨울 눈).
  소나무 삼단 원뿔 · 바위 · 다섯 잎 꽃 · 물결 도는 낚시터 · 한옥(전방)
- **줄기는 잎보다 먼저·길게 그린다** — 짧게 그렸다가 잎과 밑동이 뚝 떨어져 보인 적이 있다
- **수관의 명암은 같은 색을 어둡게·밝게만 쓴다** — 다른 색을 덮으면 탁해진다
  (봄 수관에 분홍을 통째로 덮었다가 되돌렸다). 벚빛은 작은 꽃송이로만 얹는다
- **말풍선** — 이름·안내를 화면에 그냥 얹지 않고 흰 판에 얹어 꼬리를 단다
- **하늘** — 시각에 따라 해가 하늘을 가로지르고, 밤엔 달과 별. 구름은 아주 느리게 흐른다.
  마루 너머엔 먼 바다와 산 실루엣이 **같은 처짐 곡선**을 타고 놓인다
- **날씨** — 겨울엔 눈, 봄엔 꽃잎. 자리는 해시로 고정하고 시간만 흘린다
  (매 프레임 새로 뽑으면 깜박인다)
- **기본 비례는 2등신**(`core.js` 의 `settings.prop = 'chibi'`) — 원작 비례다.
  상단 등신 버튼으로 4등신·8등신으로 바꿀 수 있고, 고른 값은 세이브에 남는다

땅은 **색별로 한 번에 칠한다**. 칸마다 `fill()` 하면 한 화면에 이천 번이 넘어
프레임이 무너진다. 먼 줄은 두 칸씩 건너뛴다 — 몇 픽셀로 뭉개지는 자리라 눈에 띄지 않는다.

> 닌텐도의 에셋(주민 캐릭터·상점 주인·아이콘·타일 그림)은 쓰지 않는다.
> 그림 문법만 따르고 그림은 전부 이 저장소의 코드가 그린다.

## 곤충 · 집 · 편지와 이사 (2026-08-26)

원작의 남은 세 축을 옮겼다.

### 곤충 (`bug.js`)

채집물과 **성질이 다르다**. 사물은 붙박여 하루 한 번을 내주지만 벌레는 살아 움직이고
달아난다. 그래서 사물 목록이 아니라 따로 관리한다.

- **잠자리채(🥅)가 없으면 못 잡는다** — 전방에서 한 번 산다(🪙 800)
- **계절과 시간대를 함께 탄다** — 반딧불이는 여름 밤에만, 겨울엔 거미 하나뿐이다
  (원작도 겨울은 휑하다). 13종
- **다가가는 것이 놀이다** — 경계 반경(58) 안에서 성큼성큼 걸으면 달아난다.
  **살금살금(Shift · 🐾)** 이면 안 달아나는 대신 걸음이 42% 로 느려진다
- 매미·풍뎅이는 **나무에 붙는다** — 움직이지 않고, 나무 곁에만 나온다
- 손이 닿는 것에서 **벌레가 사물보다 앞선다** — 달아나기 전에 손이 가야 한다

### 집 (`home.js`)

- **산다** 전방에 날마다 가구 넉 점이 들어온다(날짜 해시로 정해지니 오늘 것은 오늘만).
  14종 · 네 계열(안방·사랑방·부엌·뜰)
- **놓는다** 집 안에서 **선 자리에** 놓는다 — 심기와 **같은 규칙**이다.
  곁에 서서 Space 를 누르면 다시 거둔다
- **넓힌다** 증축을 신청하면 그 자리에서 넓어지고 **빚이 생긴다**. 다 갚아야 다음을
  신청할 수 있다 — 원작의 융자다. 단칸방 7×5 → 기와집 13×8
- **평가** 값·수·계열을 본다. 같은 계열 셋이면 +25, 다섯이면 +45.
  등급이 오르면 이름이 바뀌고 날이 바뀔 때 **평가서가 편지로 온다**
- 집은 **겉모습도 바뀐다** — 단칸방은 초가지붕, 증축하면 기와가 올라간다.
  안에만 있으면 반쪽이다

### 편지와 이사 (`mail.js`)

모든 판정은 **`onNewDay()` 한 곳에서만** 일어난다. 프레임마다 굴리면 하루가 몇 번씩 지나간다.

- **이사** 마을에 온 지 8일이 넘었는데 친밀도가 3 미만이면 하루 12% 로 **떠날 뜻**(💭)을
  비친다. 사흘 안에 **그날 부탁을 들어주고 말을 걸면** 붙잡는다(친밀도 +2 · 🎖️ +30).
  못 붙잡으면 떠나고 빈자리에 새 인물이 온다
- **편지** 감사장(선물 60%) · 새 주민 인사 · 작별(기념 가구) · **집 평가서** ·
  정든 이의 안부 · 전방 소식. **답장을 쓰면 정이 는다**(사람마다 하루 한 번)
- **우편함(📮)** 은 집 앞에 있다. 안 읽은 편지가 있으면 **깃발이 서고** 독에 배지가 붙는다 —

### 사고(史庫) — 원작의 박물관

실록을 보관하던 그 이름을 빌렸다. **도감과는 다른 자리**다.

```
도감 (village.caught)   한 번이라도 손에 넣은 것 — 팔아도 지워지지 않는다
사고 (village.donated)  들여 놓은 것 — 가방에서 한 점이 실제로 빠져나간다
```

원작이 그 둘을 갈라 둔 까닭이 있다. 잡는 것과 남기는 것은 다른 결심이다.
값나가는 것을 팔지 않고 들여 놓는 데에 값이 있어야 하므로, 기증은 금이 아니라
**명성**을 준다(20 + 값/10). 전시실은 넷 — 곤충 13 · 물고기 6 · 화석 10 · 조개 6.

**기증은 사고 앞에서만 받는다.** 어디서나 되면 건물이 마을에 있을 까닭이 없다.
등급이 오른 날에는 사고에서 편지가 온다.

### 선물

정을 쌓는 두 번째 길이다. 부탁은 **그 사람이 청한 것**을 가져다 주는 것이고,
선물은 **내가 골라서** 주는 것이다.

- 주민 곁에서 가방 시트를 열면 항목마다 `🎁 <이름>에게` 가 붙는다
- 사람마다 **좋아하는 갈래**가 있다(인물 id 로 정해지니 늘 같다).
  좋아하는 것이면 친밀도 +3, 아니면 +1. 값이 200 이상이면 +1 더
- 사람마다 **하루 한 번**. 다음 날 **답례 편지**가 온다

### 벽지와 장판

가구보다 먼저 방의 인상을 바꾸는 것이 이 둘이다. 벽지 5 · 장판 5.
전방에 날마다 **벽지 한 벌 · 장판 한 벌**이 들어오고(날짜 해시), 산 것은 집 시트에서
갈아 끼운다. 기본이 아닌 것을 바르면 집 평가가 각각 **+12**.

## 마을 이름과 깃발 · 주민끼리의 대화 · 계절 행사 (2026-08-26)

원작 모방의 **마지막 잔가지 셋**이다.

### 마을 이름과 깃발 (`town.js`)

- 이름은 **마을 씨앗으로 뽑는다**(같은 마을이면 늘 같다). 게시판(📋)이나 깃대(🚩)에서
  언제든 바꾼다. 여덟 자까지
- 깃발은 **바탕 6 · 무늬색 5 · 무늬 8** 을 고른다. 점을 찍는 도트 편집기는 이 판에 맞지
  않는다 — 고르는 것으로 충분하다. 깃대에 걸리고 시트에서는 실제 그림으로 미리 보인다
  (`villageView.flagIconOf` 가 캔버스로 뽑아 준다)
- 게시판이 여태 주민 시트를 열고 있었는데 이제 제 몫이 생겼다 —
  이름·깃발·오늘과 다음 행사·마을 현황

### 주민끼리의 대화 (`folk.js`)

주민이 나만 바라보고 서 있으면 마을이 아니라 상점가다.

- **어슬렁** 제 자리 둘레 **64 안에서만** 돈다. 멀리 걷게 하면 부탁을 들어주려고
  사람을 찾아 헤매게 된다 — 그건 예전에 안 하기로 했다
- **잡담** 150 안에 선 두 사람이 가끔 서너 마디를 번갈아 주고받는다.
  대화는 마을의 지금을 말한다(계절·시간대·마을 이름·오늘 행사·다른 주민)
- **엿듣기** 그 대화를 **끝까지** 곁에서 들으면 두 사람과 정이 는다 (하루 한 번).
  자리를 뜨면 안 는다

### 계절 행사

양력으로 고정한 여덟 날 — **설날 · 대보름 · 삼짇날 · 단오 · 칠석 · 백중 · 한가위 · 동지**.
음력을 계산하려면 표가 하나 더 들고, 이 판에서 얻는 것보다 드는 것이 크다.

| 그날 | 무엇이 달라지나 |
|---|---|
| 설날 | 주민에게 말을 걸면 **세배** — 세뱃돈(정이 깊을수록 두둑하다). 사람마다 한 번 |
| 대보름·한가위 | 밤에 **달이 크고 둥글다**. 부럼/과일 값 갑절 |
| 삼짇날 | 계절과 무관하게 **나무마다 벚빛**이 돌고 꽃잎이 흩날린다. 꽃 값 갑절 |
| 칠석 | 밤하늘의 **별이 갑절**. 곤충 값이 오른다 |
| 백중 | 밤에 **불꽃**이 오른다. 물고기 값이 오른다 |
| 단오·동지 | 꽃/열매 값이 오른다 |

행사는 **날짜만 본다** — 세이브에 남길 것이 없다. 그날이면 그날이다.
그날 아침에 편지로 알린다.

## 나무 흔들기 — 열매만 떨어지지 않는다 (2026-08-26)

원작에서 나무를 흔들면 열매만 떨어지지 않는다. 가구가 걸리고, 돈주머니가 떨어지고,
재수 없으면 **벌집**이 떨어진다. 그 셋이 있어야 나무 앞에서 손이 망설여진다.

```
벌집 8%   벌떼가 쏟아져 쫓아온다
가구 6%   창고로 들어간다 (하루 둘까지)
돈   5%   🪙 300~900 (하루 하나까지)
그밖      여느 때처럼 열매
```

- **하루 몫이 있다.** 없으면 나무를 도는 것이 곧 돈을 찍는 일이 된다 — 원작도 막아 두었다.
  몫이 끝난 칸에 걸리면 **열매로 떨어진다**(다음 칸으로 흘려보내지 않는다)
- **벌떼(🐝)** 는 원작 그대로 **쫓아온다**. 달아나 320 을 벌리거나 6초를 버티면 흩어지고,
  붙잡히면 쏘인다. **잠자리채로 받아치면 잡힌다**(값 480) — 그 자리도 원작대로다
- 쏘인 날은 **하루 종일 걸음이 무겁다**(80%). 상단에 🐝 가 뜬다
- 말벌은 **저절로 나오지 않는다**(`swarm: true` — `poolNow` 가 걸러낸다).
  나무를 흔들어야 만나고, 잡으면 도감과 사고에 들어간다
- 흔들기 판정은 사람이 누를 때만 도는 자리라 **공용 난수를 쓴다**
  (프레임마다 도는 `bug.js`·`folk.js` 와 다르다)

## 날씨 — 하늘이 그날을 정한다 (2026-08-26)

**날짜로 정해진다.** 세이브에 남길 것이 없다 — 같은 날이면 같은 하늘이다.
계절이 확률을 정하고(겨울엔 비 대신 눈), 하늘을 봐야 하는 행사날은 못을 박았다.

```
맑음 ☀️   해와 달과 별이 다 보인다
흐림 ☁️   구름이 짙고 많다. 해와 별이 가린다
비   🌧️   빗줄기와 땅에 튀는 자국. 화면이 어둡다
눈   🌨️   겨울에만. **겨울이라고 늘 오지는 않는다**
```

- **비 오는 날에만 나오는 것** — 🐌 달팽이 · 🪱 미꾸라지.
  거꾸로 **나는 벌레(나비·잠자리·매미)는 비에 숨는다**(`rain: 'no'`).
  원작도 비에는 나는 것이 줄고 기는 것이 는다
- **달·별·불꽃 행사날은 맑다**(`sky: 'clear'`). 한가위에 비가 오면 큰 달을 못 본다 —
  그 하루만은 하늘을 고정한다. 동지는 반대로 눈이다
- 겨울 눈이 **계절이 아니라 날씨**로 옮겨 갔다. 그래야 눈 오는 날이 반갑다
- `data-village.js` 는 `core` 를 모른다(불러오는 차례가 앞이다). 그래서 날씨 해시를
  그 파일에 따로 두었다
- **부탁도 같이 고쳤다** — 여태 표에서 그냥 뽑아 한겨울에 매실을 청했다.
  이제 `VD.pick` 을 거쳐 **지금 나는 것 중에서만** 청한다

## 순무 장 — 원작의 카부 (2026-08-26)

원작에서 **유일하게 값이 오르내리는** 축이다. 채집은 값이 정해져 있고 부탁은 값을
치러 주지만, 순무만은 사 두고 기다렸다가 판다. **마을에 요일이 생기는 것도 이것 하나
때문이다.**

```
산다   일요일 오전에만 장이 선다. 그날 살 값 90~110. 열 개 묶음, 한 주 900개까지
판다   월~토, 오전과 오후에 값이 다르다 (하루 두 번 바뀐다)
썩는다 다음 일요일이 오면 썩는다. 개당 10 에나 나간다
```

그 주의 시세는 **네 무늬 중 하나**를 탄다(그 주의 씨앗으로 정해진다) —
**파동**(0.8~1.4 사이 오르내림) · **내림**(월요일부터 계속) · **급등**(한중간에 한 번) ·
**폭등**(후반에 서너 배까지).

- 세이브에는 **가진 것만** 남는다(수·산 값·산 주). 시세는 날짜에서 다시 뽑는다 —
  저장해 두면 세이브를 고쳐 값을 바꿀 수 있게 된다
- 시세표는 **지나간 칸만** 보여 준다. 앞일을 알면 놀이가 아니다
- 요일은 **세이브의 날짜 칸**에서 뽑는다(`(day + 4) % 7`, 1970-01-01 이 목요일이다) —
  하루 몫·부탁과 같은 기준이어야 어긋나지 않는다
- 일요일 아침에는 편지로 알린다

**여기서 `today()` 의 부호 오류가 드러났다.** `getTimezoneOffset()` 은 KST 에서 -540 이라
그 고장 시각은 `getTime() - offset*60000` 인데, 옛 식이 9시간을 **빼서** 날이 자정이 아니라
**저녁 여섯 시에** 바뀌고 있었다. 요일이 어긋나 잡혔다.

## 주민의 성격 · 내가 먼저 쓰는 편지 (2026-08-26)

### 성격 여섯 (`FOLK_TYPES` · `folk.typeOf`)

원작의 성격 유형 자리다. **인물 id 로 정해지니 늘 같다**(세이브에 남기지 않는다).

| 성격 | 결 | 청하는 갈래 | 반기는 선물 |
|---|---|---|---|
| 🍶 호협 | 활달하고 거침없다 | 물고기·광물·열매 | 물고기 |
| 📜 근엄 | 말이 짧고 무겁다 | 광물·씨앗·화석 | 광물 |
| 🌸 다정 | 살갑고 말이 곱다 | 꽃·열매·조개 | 꽃 |
| 📖 학구 | 아는 것을 꼭 말한다 | 씨앗·광물·화석 | 화석 |
| 🎭 익살 | 한마디에 농이 섞인다 | 열매·물고기·곤충 | 곤충 |
| 🌾 우직 | 순박하고 곧다 | 열매·씨앗·조개 | 열매 |

- **말투**가 갈린다 — 부탁할 때·받았을 때·오늘 부탁이 끝난 뒤가 다 다르다
- **청하는 갈래**가 갈린다. 사람마다 청하는 것이 늘 비슷해야 그 사람으로 기억된다
- **선물로 반기는 갈래**도 성격이 정한다(전에는 id 해시였다)
- 편지 문구도 성격을 탄다
- 문구의 `{it}`·`{n}`·`{have}` 는 `folk.say()` 가 채운다

### 내가 먼저 쓰는 편지 (`mail.write`)

원작의 우체국 자리다. **답장과는 다른 칸을 쓴다** — 답장은 온 편지에 답하는 것이고,
이것은 소식이 없어도 먼저 마음을 전하는 것이다. **곁에 없어도 된다**는 점이 직접
주는 선물과 다르다.

- 사람마다 **하루 한 번**. 예순 자까지. 친밀도 +1
- **다음 날 답장이 온다**(성격대로 답하고, 절반쯤은 선물이 붙는다)
- 같은 날 부치고 답장까지 쓰면 친밀도가 둘 오른다 — 칸이 다르기 때문이다

## 꽃 교배 · 전방이 자란다 · 별똥별 · 잡초와 마을 평가 (2026-08-26)

### 꽃 교배

**심은 꽃 곁(한 칸 반 안)에 다른 꽃이 있으면** 드문 색이 핀다 — 금낭화 · 자란 · 홍매.
판정은 **자리 해시**로 한다(무작위가 아니다). 심어 놓고 사흘 뒤에 와도 같은 결과가
나오고, **어디에 심을지가 놀이가 된다.** 교배로 핀 꽃은 색이 달라 한눈에 보인다.

드문 꽃은 무게가 0 이라 **저절로는 피지 않는다** — `VD.pickHybrid()` 로만 나온다.

### 전방이 자란다

원작의 상점이 커지던 자리다. **전방에 판 금 누계**로 오른다.

```
전방          🪙 0        가구 4점 · 웃돈 없음
저잣거리 전방  🪙 3만      가구 5점 · +4%
상단(商團)     🪙 12만     가구 6점 · +8%
도가(都家)     🪙 40만     가구 7점 · +12%
```

마을을 부지런히 돌수록 전방이 커지고, 커진 전방은 **물건이 늘고 값을 더 쳐준다**.
겉모습(건물 크기)도 같이 커진다.

### 별똥별과 소원

밤 맑은 하늘에 이따금 별이 흐른다. 그때 **손에 닿는 것이 없는 채로** 손을 쓰면
소원을 빈다(하룻밤 세 번까지, 같은 별에는 한 번). 다음 날 **별조각**이 편지로 온다.

흐르는 때와 자리는 **시각을 잘라 해시로** 정한다 — 난수를 쓰지 않으니 프레임 수와
무관하고 세이브에 남길 것도 없다. 안내 말풍선은 **땅을 다 그린 뒤에** 얹는다
(하늘에 얹었더니 바다 띠에 덮였다).

### 잡초와 마을 평가

- **잡초(🌿)** 는 날마다 한둘씩 는다(최대 40). 자리는 세이브에 남으니 뽑기 전엔
  사라지지 않는다 — 그래야 "며칠 안 왔구나" 가 눈에 보인다
- **마을 평가** = 100 − 잡초×3 + 꽃(최대 30) + 심은 것×2 + 집 평가/4 + 사고 종수×2.
  거친 마을 → 손이 간 마을 → 정갈한 마을 → 아름다운 마을 → 이름난 마을
- **평가가 높으면 주민이 잘 떠나지 않는다**(등급 한 단마다 떠날 판정 18% 감소).
  그게 이 점수의 값이다. 평가서는 **월요일 아침**에 온다

## 옷 — 침선방(針線房) (2026-08-26)

원작의 재봉실 자리다. 궁중에서 바느질을 맡던 이름을 빌렸다.
마을 가운데 왼쪽, 전방 아래에 선다.

고르는 것은 넷 — **겉옷**(평상복·도포·두루마기·갑옷) · **머리**(맨머리·상투·댕기·유건·
갓·족두리·전립) · **옷 빛**(여덟) · **덧옷**.

- 사면 **옷장에 남고**(`owned`), 옷장에 있는 것만 입는다. 값이 0 인 것은 처음부터 있다
- **날마다 바뀌는 진열을 두지 않았다.** 가구·벽지와 다른 점이다 —
  옷은 취향이라 "오늘 것" 으로 막으면 답답하다. 값이 문턱이면 충분하다
- 겉모습만 바뀐다. 원작의 옷도 그렇다

### `sprite.js` 를 한 줄도 고치지 않았다

고른 값이 그대로 `look`(armor · helm · cape)과 `color` 로 들어간다.
다만 **스탬프 캐시가 `ref.id` 로만 갈린다** — 그대로 두면 갈아입어도 옛 그림이 나온다
(실제로 그랬다). 그래서 그릴 때 **차림표(`wear.sig()`)를 붙인 가짜 id** 를 넘긴다.

```js
ref: { id: ref.id + '#' + wear.sig(), rarity: ref.rarity }
```

`bake()` 가 사람에 대해 `o.ref` 에서 읽는 것은 `rarity` 뿐이고 그건 따로 넘기므로,
이 최소한의 가짜로 충분하다. **도감의 인물 그림은 그대로다** — 옷은 내 것이지
그 사람의 것이 아니다.

```
때(時)       계절·시간대·날씨·행사를 못 박고, 날짜를 민다
균형 손잡이   규칙 상수 19개 + 걸음 배속
QA 프리셋     확인하려는 상황 14가지 + 스냅샷 세 칸
점검 · 백업   세이브 조각 꺼내기/덮기 · 어드민 자가점검 9항목
```

### 이 판에서 가장 값진 탭은 '때' 다

이 마을은 **실제 시계에 크게 기댄다** — 계절·시간대·날씨·행사·요일이 다 날짜에서
나온다. 한가위 밤의 큰 달도, 순무 장이 서는 일요일 오전도, 비에만 나오는 달팽이도
그날이 와야 본다. 그래서 어드민의 몫은 **그날로 가는 것**이다.

- `time.season` · `time.phase` · `time.weather` · `time.event` 를 못 박는다
  (비워 두면 실제 시계). 게임 창은 **새로고침 없이** 다음 프레임부터 듣는다
- `time.dayShift` 로 날짜를 민다 — 하루를 넘기면 채집물이 여물고 부탁이 새로 붙고
  편지가 오고 잡초가 늘고 이사가 판정된다. **되돌리면 원래 날로** 돌아온다

### 손잡이는 세이브와 다른 칸에 산다

`core.js` 에 사가고와 **같은 이름**으로 옮겨 두었다 —
`TUNE_KEY`(`yeoksa-village/tune`) · `POKE_KEY` · `tuned/setTune/clearTune`.

- 세이브에 섞으면 프로필마다 규칙이 달라지고, 세이브를 넘길 때 규칙까지 따라간다.
  규칙은 "이 기기의 사정" 이지 진행이 아니다
- **자가진단과 데모는 읽지 않는다**(`DG_NO_TUNE`). 손잡이를 잡아 둔 기기에서 판정과
  스크린샷이 흔들리면 안 된다 — 씨앗을 고정한 것과 같은 이유다.
  `_test.html` 의 **'자가진단은 어드민 손잡이를 읽지도 쓰지도 않는다'** 가 그 못이다
- 대부분은 **모듈이 켜질 때 한 번** 읽는다 → 바꾼 뒤 게임 창 새로고침.
  **걸음 배속과 때만** 매번 읽어 곧바로 듣는다
- 고친 뒤 `POKE_KEY` 를 두드리면 게임 창이 세이브를 다시 읽는다.
  게임이 10초마다 저장하므로, 안 그러면 어드민이 고친 값이 곧 덮인다

어드민은 **PC 단독판에 들어가지 않는다** — `build-single.mjs` 는 `index.html` 의
`<script src>` 만 훑기 때문이다.

## 공사(工事) — 땅을 고친다 (2026-08-26)

원작(동물의숲)에서 마지막까지 남아 있던 축이다. 남아 있던 까닭은 **이 마을이
좌표 해시로 생기기** 때문이다(`village.js` 의 `tileAt`) — 타일을 세이브에 적어 두지
않으니 고칠 자리가 없었다.

### 타일 표가 아니라 덮개층

```
save.village.terrain = { "tx,ty": 'path' }      ← 고친 칸만
```

`tileAt` 이 해시를 풀기 **전에** 이 표를 본다. 그래서

- 안 고친 마을은 세이브가 한 자도 늘지 않는다 (지금까지의 마을이 그대로다)
- 되돌리면 칸을 **지운다**. 원래 해시로 돌아가고 세이브도 도로 줄어든다
- 마을 크기·해시·투영은 한 줄도 안 건드렸다

"늘 같은 마을" 이라는 전제도 살아 있다 — 고치지 않은 칸은 여전히 해시가 정한다.

### 절벽은 넣지 않았다

원작의 공사는 셋이다 — 길 · 물길 · **절벽**. 앞의 둘만 옮겼다.
절벽은 땅에 **높이**가 있어야 하는데, 이 판의 투영(`village-view.js` 의 `project`)은
마을 좌표를 구면에 감아 화면에 놓는 함수라 높이 축이 아예 없다. 높이를 넣으려면
투영·그림자·통행·주민 걸음이 한꺼번에 뒤집힌다. 그림이 곧 이 게임인 판이라,
얻는 것보다 잃는 것이 크다고 보고 뺐다.

### 규칙

| 무엇 | 어떻게 |
|---|---|
| 여는 것 | 전방의 **개토패(開土牌)** 🪧 4,800. 사기 전에는 독에 공사 단추가 없다 |
| 자리 | **선 칸을 가운데로 한 3×3**. 멀리서 마을을 주무르지 못한다 |
| 깔 것 | 흙길 300 · 돌길 600 · 물길 900 · 풀밭 500 · **모래펄 1,400** · 되돌리기 150 |
| 못 하는 곳 | 마을 밖 · 사물이 선 칸 · 주민이 선 칸 · (물길만) 내가 선 칸 |

**모래펄이 가장 비싼 것은 일부러다.** 사물은 타일에서 나오므로(`buildProps`)
모래를 깔면 조개가 나고 낚시터가 설 수 있다. 값이 그 문턱이다.
반대로 풀을 물로 바꾸면 그 칸의 하루 몫이 사라진다.

**돌길(`stone`)은 공사로만 생긴다.** 마을 생성 해시는 이 타일을 내지 않는다.

### 사물 id 를 자리로 지었다

공사를 넣으며 드러난 것이다. `buildProps` 가 사물 id 를 **순번**으로 지었는데
(`p0`·`p1`…), 공사로 사물이 하나 생기거나 사라지면 뒤 번호가 전부 밀린다.
그러면 오늘 이미 딴 표시(`used[propId]`)가 **엉뚱한 나무에 붙는다.**
id 를 자리로 바꿨다(`p<tx>_<ty>`). 진단의
'공사를 해도 오늘 딴 표시가 다른 사물로 옮겨 가지 않는다' 가 그 못이다.

### 화면

독의 🪧 공사 단추는 **개토패를 산 순간** 선다(`ui.js` 의 `syncDock` 을 `changed` 에서도
부른다 — 시트를 여닫을 때만 돌리면 사고 나서 한 번 여닫기 전에는 안 뜬다).
시트는 3×3 격자를 그리고, 고른 칸을 **좌표가 아니라 선 칸에서의 어긋남(dx,dy)** 으로
들고 있는다. 그래서 걸어가면 격자도 따라오고 고른 칸도 함께 옮겨 간다.
무엇이 막는지는 `terrain.can()` 이 **말로** 돌려주므로 화면은 그걸 단추에 적기만 한다.

어드민의 손잡이는 하나뿐이다 — `build.costMul`(삯 배수).
무엇을 깔 수 있는지는 규칙이지 손잡이가 아니다.
