# saga-forest 전면 리뉴얼 작업

대상 프로젝트:

https://smh8627-jpg.github.io/swbins/saga-forest/

현재 프로젝트를 완전히 새로 만드는 것이 아니라 **기존 saga-forest 코드를 최대한 재사용하면서 품질을 크게 끌어올리는 방향**으로 작업한다.

핵심 목표는 다음 5가지다.

1. 토큰 사용량 최소화
2. 기존 기능 최대한 보존
3. 실제 3D GLB/GLTF 에셋 기반 그래픽으로 전환
4. 숲/필드의 지형지물과 콘텐츠를 대폭 증가
5. 모바일 세로/가로 모드 모두 완벽하게 지원

---

# 0. 최우선 규칙 — 토큰 절약

이번 작업에서 가장 중요한 것은 **불필요한 코드 재작성과 파일 전체 재출력을 방지하는 것**이다.

Claude Code는 작업 전에 반드시 프로젝트 구조를 먼저 확인한다.

## 반드시 지킬 것

- 기존 코드를 무조건 처음부터 다시 작성하지 않는다.
- 기존 파일을 먼저 분석한다.
- 필요한 파일만 수정한다.
- 정상 작동하는 기능은 건드리지 않는다.
- 동일한 기능을 새 시스템으로 중복 구현하지 않는다.
- 기존 유틸리티/상태관리/렌더링 구조를 재사용한다.
- 거대한 단일 파일로 합치지 않는다.
- 이미 존재하는 함수는 가능하면 재사용한다.
- CSS도 전체 교체하지 말고 필요한 부분만 수정한다.
- 기존 UI 기능을 삭제하지 않는다.
- 기존 저장 데이터 구조를 깨뜨리지 않는다.
- 기존 게임 로직을 가능한 한 유지한다.

## Claude Code 작업 방식

각 단계마다:

1. 현재 구조 확인
2. 변경 대상 파일 결정
3. 최소 변경
4. 테스트
5. 다음 단계 진행

파일을 읽을 때도 전체 파일을 무조건 읽지 말고 필요한 부분을 우선 검색한다.

예:

- scene
- renderer
- player
- terrain
- camera
- controls
- asset
- mobile
- ui
- resize
- orientation

등의 키워드로 먼저 검색한다.

# 2. 그래픽 방향 전환

현재 프로젝트의 가장 큰 문제는:

- 지형이 단순함
- 오브젝트가 부족함
- 화면이 비어 보임
- 게임 세계가 작아 보임
- 기본 Primitive 위주의 느낌
- 모바일 웹게임처럼 보임

이를 개선한다.

목표:

**"모바일에서 플레이하는 작은 3D 숲속 오픈월드 RPG"**

느낌으로 만든다.

참고 분위기:

- Animal Crossing
- Zelda 계열의 밝은 3D 필드
- 현대 모바일 3D RPG
- 캐주얼 오픈월드
- 판타지 숲
- 탐험형 RPG

단, 특정 게임의 그래픽을 그대로 복제하지 않는다.

# 3. 실제 3D 에셋 사용

가능하면 직접 만든 Box/Sphere/Cylinder 조합 대신 실제 3D 에셋을 사용한다.

기본 포맷:

- GLB
- GLTF

Three.js GLTFLoader를 이용한다.

가능하면:

- Draco 압축
- Meshopt
- KTX2/Basis texture

등 모바일 최적화 기술을 적용한다.

three.js의 GLTFLoader가 Draco, Meshopt, KTX2 등의 확장을 지원하므로 이를 활용한다.

# 15. 플레이어

필요 애니메이션:

- Idle
- Walk
- Run
- Attack
- Hit
- Dodge

GLB에 animation이 없으면 최소 Idle/Walk라도 구현한다.

AnimationMixer 기반으로 관리한다.

# 29. 모바일 성능 최적화

가장 중요하다.

적용:

- devicePixelRatio 제한
- 모바일 해상도 scaling
- shadow map 낮춤
- 그림자 거리 제한
- fog 활용
- frustum culling
- LOD
- InstancedMesh
- object pooling
- asset caching
- particle pooling

모바일에서 불필요하게 4K 텍스처를 사용하지 않는다.

# 42. 소리(音) — 절차적 효과음 신설 (2026-09-10)

다섯 판 중 사가블로(`sfx.js`, 33종)·사가고(`audio.js`)·사가스토리(`sfx.js`+CC0
BGM)는 이미 소리가 있는데 **이 판만 여태 무음**이었다 — 계절·낚시·채집·유성·
편지 등 "삶의 결" 콘텐츠가 다섯 판 중 가장 풍부한데 정작 무음이라 손실이
크다는 판단으로 최우선으로 뽑혔다(다른 판에서 빌려올 기능 후보 조사, 1위).

**사가블로 `js/sfx.js`를 그대로 본으로 삼았다** — WebAudio 로 절차적으로
낸다(에셋 없음), 겹은 tone·noise·chime 셋, 첫 입력 전엔 못 낸다(`unlock()`이
스스로 문서에 건다), 요청은 꺼져 있어도 `_tail()`에 남는다(판정 층과 소리
층을 가른다), 같은 소리는 최소 간격, `AudioContext`는 한 번만. 소리 스무 가지:
발소리 다섯(흙길·돌길·물길·풀밭·모래펄, 공사 다섯 갈래와 같은 이름) · 낚시
셋(입질·놓침·건짐) · 곤충 셋(벌떼·달아남·채집) · 문 둘(집·굴, 다른 잔향) ·
레벨업 · 계절 전환 · 유성 · 편지 · 기증 · 선물 둘(그냥/아주 반김).

**`village.js`·`animal.js`·`weather.js`·`town.js`는 한 글자도 안 건드렸다.**
두 갈래로 듣는다 — ① 이미 있는 이벤트(`village:fish`·`village:bug`·
`village:home`·`village:cave`·`levelup`)를 `js/sfx.js`가 스스로 구독 ②
판정 파일엔 없지만 **읽기 전용 공개 함수로 값이 드러나는 것**(발소리 지형·
계절·유성)은 `js/sfx.js`가 220ms마다 폴링해서 값이 바뀔 때만 운다
(`village.raw()`·`village.tileAt()`·`villageData.season()`·`town.starNow()`
전부 이미 있던 읽기 전용 함수라 판정을 안 건드리고도 듣는다). 딱 세 자리에만
한 줄씩 보탰다 — `mail.js`의 `put()`(새 편지가 오면 알아야 하는데 그런
이벤트가 없었다) · `ui.js`의 기증·선물 결과 처리(이미 결과가 난 다음의 UI
반응 지점이라 안전하다).

상단 🔊(`#btn-sound`, `game.js`의 `bindTopbar()`가 다른 아이콘 버튼과 같은
결로 잠금·해제) 로 끄고 켠다(`core.save.settings.sound`, 다른 판과 같은 이름).

검증 — `_test.html`에 소리표 완결성·꺼져도 기록됨·이벤트 연결·계절/유성
폴링(값을 잠깐 바꿔치기해 "바뀌었을 때만 운다"를 확인, `season()`이 실제
달력 달을 읽어 진단 중엔 못 바꾸기 때문) 항목 여덟을 더했다. 자가진단
237→245(3회 동일). `_sfxcheck.html`(스무 소리를 하나씩 내 보는 확인용
페이지, `unlock()`을 직접 불러 브라우저 제스처 없이도 들어볼 수 있다)도
새로 두었다.

**실기 확인 전이다** — 실제로 소리가 나는지·거슬리지 않는지는 사용자가
직접 들어봐야 한다. `_sfxcheck.html`을 열어 스무 소리를 순서대로 들어보고,
실제 플레이에서 발소리 간격·볼륨이 적당한지 확인해 줄 것.

# 42-3. 움직이는 모션을 더 자연스럽게 — 회전 스냅 없앰 (2026-09-10)

인물의 걷는 방향(`facingYaw`)과 걷는 짐승 일곱 종(사슴·여우·늑대·토끼·
다람쥐·오리·새)의 몸 회전이 둘 다 **매 프레임 순간 대입**이었다 — 방향을
바꾸면 한 프레임 만에 홱 돌았고, 짐승은 아예 회전이 없어 옆으로 미끄러지듯
보였다. 최단 경로 각도 보간(`angleLerp`)과 프레임 길이와 무관한 지수감쇠
계수(`turnLerpK`, `village3d.turnRate` 손잡이, 기본 8)를 새로 얹어 몸·
카메라(어깨너머 모드)가 같은 값으로 같이 부드럽게 돈다. 짐승은
`TURNING_KIND` 표에 있는 일곱 종만 이전 프레임 자리와 비교해 방향을 잡는다
(나무·건물처럼 안 움직이는 건 계산을 안 한다). 자가진단 249→253(3회 동일).

# 42-4. 개구리·뱀 보탬 + 짐승 걷기 애니메이션 (2026-09-10)

"더 추가할 캐릭터·동물이 없는지" 확인 — 캐릭터(주민·NPC 외형)는 이미
공유 `HEROES` 105명 + MPFB2 20종이 표 기본이라 더 채울 자리가 없었다.
동물은 바이옴별로 세어 보니 mushroom 이 여우 하나뿐이라 진짜 비어 있었다
— `saga-go`의 CC0 짐승(Quaternius)에서 **개구리(mushroom·dark)·뱀
(rocky·dark)**을 옮겨 보탰다(9종 §42-3의 `TURNING_KIND`에도 합류).

**덤으로 찾은 것** — 개구리·뱀 GLB를 열어 보다가 사슴·여우·늑대
(Quaternius) GLB에도 Idle·Walk 클립이 원래 있었는데 3D 화면이 짐승을
나무·바위처럼 정지 오브젝트로만 세워(`mixer`를 안 만듦) 그 클립을 한 번도
안 썼다는 게 드러났다. `asset3d.js`의 `buildGeneric()`이 원본에 클립이
있으면 `hero`와 같은 결로 mixer·actions·clipMap 을 실어 주게 고쳤고,
`syncScatter()`가 `playAction()`으로 걷는 동안 walk·멈추면 idle 을 튼다.
사슴·여우·늑대·개구리·뱀 다섯 종이 이제 실제로 다리가 움직인다(토끼·

# 44. 3D NPC "안 보인다" 재신고 — 진짜 원인은 안개였다 (2026-09-10)

2026-09-09에 카메라~플레이어 거리를 늘려 "고쳤다"고 남겼지만 사용자가
"아직도 안 보임"으로 다시 신고했다. 실제 좌표를 재 보니(Node로 `village.js`를
그대로 불러 좌표만 계산) 숲 NPC 여섯이 마을 중심에서 **67~113m** 떨어져
있는데, `village-view3d.js`의 안개 먼 끝(`FOG_FAR`)이 **160m**뿐이었다 —
맑은 날에도 절반 넘게 안개에 덮이고 비·눈이면 80~136m로 더 좁아져 가장 먼
NPC는 거의 안 보였을 것이다. NPC는 거리 컬링이 없어(원래부터 그렇게
설계됐다) 장면엔 계속 서 있었다 — 안개가 시각적으로 삼켰을 뿐이다.

`FOG_FAR` 160 → 320(`FOG_NEAR` 30 그대로). fog는 셰이더 블렌딩 값이라
렌더 비용이 늘지 않는다. 자가진단 259/259 그대로(세 번 동일, fog는 픽셀
검사가 아니라 새 항목 없음). `sw.js` → `village-v0.54.0`.

**곧바로 사용자가 "안개는 중요 하지 않으니 제거 하던지 옵션에 키고
끄는걸 추가해 끄는게 기본이고"로 위 수치 조정 자체를 되돌렸다.** 안개
거리를 맞게 늘렸는지 다투는 대신, **안개를 아예 옵션으로 빼고 기본을
꺼짐으로** 정하는 쪽이 더 단순하고 확실하다 — 꺼져 있으면 거리와 무관하게
NPC·모든 사물이 또렷이 보인다. `village3d.fog` 손잡이(`core.tuned`/`setTune`,
새로고침해도 유지, `village3d.quality`와 같은 결) 신설, 기본값 0(꺼짐).
`init()`의 `scene.fog` 생성과 `syncSky()`의 안개 갱신을 `FOG_ON()`/`scene.fog`
존재 여부로 감쌌다 — 꺼져 있으면 `scene.fog`가 아예 `null`이라 안개 계산
자체가 안 돈다. ⚙️ 설정 시트(그래픽 품질 옆)에 켜짐/꺼짐 버튼 신설
(`ui.js`의 `fog-toggle`). 위 `FOG_FAR` 320 값은 **죽지 않았다** — 사용자가
직접 안개를 켜면 그 넉넉해진 거리로 켜진다. 자가진단에 기본값·손잡이
왕복 확인 하나 추가, 259 → **260**(세 번 동일).

# 부록 · 코드로 그리지 말고 에셋으로 (다섯 판 공통 방침)

**사용자 지시 (2026-08-28). 다섯 판에 다 같이 적용한다.**

> "스크립트로 쓰고 있는 것들은 다 에셋으로 변경 했으면 해."
> "스크립트는 오직 이벤트나 기능들."
> "도감 일러스트나 캐릭터들도 에셋이 없는지 확인해주고 추가해줘. UI 도."

즉 **코드가 도형·그림을 조립해 만들던 것은 전부 실제 에셋으로 갈아 끼운다.**
3D 모델만이 아니다 — **도감 일러스트 · 인물 초상 · UI 그림**까지 포함한다.
남는 스크립트는 **이벤트와 기능(판정 · 규칙 · 상태)** 뿐이다.

## 왜

사용자가 먼저 고른 것이 **품질**이다. "스크립트로 그려서 퀄리티가 떨어진다 —
에셋을 써라" 가 이 축의 시작이었고, 받을 수 있는 CC0 에셋이 이 판의 결
(한옥 · 갓 · 도포)과 다르다는 것을 알고도 **"둘 다 얹는다(품질 우선)"** 를 골랐다.
그러니 **"결이 안 맞아서" 는 안 하는 이유가 되지 못한다.**

## 어떻게

- 새 작업을 잡을 때 **그 판에서 아직 코드가 그리는 것부터 센다.**
  3D 소품 · 건물 · 인물뿐 아니라 **캔버스로 그리는 초상 · 카드 · 아이콘**까지
- **되돌림 길은 지우지 말고 손잡이로 남긴다.** 에셋을 못 받는 자리가 실제로 있다 —
  `file://` 단독판 · 낮은 품질 등급 · 오프라인. 그때는 조용히 옛 그림으로 돌아간다
- **에셋을 못 구하면 그 사실을 알린다.** 이 망은 GitHub(`raw.githubusercontent.com` ·
  `api.github.com`)만 열려서 미러에 없는 것은 못 받는다. CC0 로 존재하지 않는 것
  (예: 특정 인물 일흔의 초상)은 **"안 한다" 가 아니라 "이래서 막혔고 대신 이것을
  할 수 있다"** 로 보고한다 — 사용자가 직접 받아다 줄 수도 있다
- 출처와 라이선스는 판마다 `assets/ASSET_LICENSES.md` 에 적는다.
  **공개 저장소라 재배포가 안 되는 것은 애초에 받지 않는다.**
  저작자 표시가 필수인 것(CC-BY)은 표시 문구를 같이 옮긴다
- **원작사의 실제 에셋은 넣지 않는다.** 이 규칙은 그대로다
