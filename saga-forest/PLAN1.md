# SAGA-FOREST Godot 4 3D 전환 작업지시서

## 0. 최우선 원칙

이 프로젝트의 최우선 목표는 다음과 같다.

1. 기존 `saga-forest`의 게임 컨셉과 핵심 재미를 유지한다.
2. HTML/JS 기반 구조를 Godot 4.x 기반 프로젝트로 전환한다.
3. 기존 2D/웹 게임의 단순한 느낌을 개선하고 **3D 모바일 게임 수준의 시각적 완성도**를 목표로 한다.
4. 모바일 세로/가로 화면을 모두 지원한다.
5. **Claude Code 토큰 사용량을 최소화한다.**
6. 필요하지 않은 파일 전체 읽기/전체 재작성/반복 분석을 금지한다.
7. 기존 기능을 무조건 버리지 말고 필요한 기능만 Godot 구조로 이전한다.
8. 한 번에 거대한 코드를 생성하지 말고 단계적으로 구현한다.
9. 기능 구현 전에 현재 프로젝트 구조를 먼저 짧게 분석한다.
10. 작업 완료 후 실제 실행 가능한 Godot 프로젝트를 만드는 것을 목표로 한다.

---

# 1. 대상 프로젝트

기존 프로젝트:

https://smh8627-jpg.github.io/swbins/saga-forest/

현재 웹 버전을 먼저 확인하고 게임의 핵심 구조와 콘텐츠를 파악한다.

단, 전체 소스코드를 무작정 읽지 않는다.

먼저 다음만 확인한다.

- package/config 파일
- 진입 HTML
- 주요 JS 파일
- 게임 상태 관리 코드
- 플레이어 관련 코드
- 맵 관련 코드
- UI 관련 코드
- 저장 데이터 관련 코드
- 핵심 게임 로직

분석 결과는 길게 설명하지 말고 다음 형식으로 출력한다.

```text
[PROJECT ANALYSIS]

현재 구조:
- ...

핵심 게임 시스템:
- ...

재사용 가능한 게임 설계:
- ...

Godot에서 새로 구현할 시스템:
- ...

버릴 수 있는 기존 코드:
- ...

예상 Godot 구조:
- ...
```

분석만 하고 바로 전체 코드를 작성하지 않는다.

# 2. 가장 중요한 토큰 절약 규칙

Claude Code는 다음 규칙을 반드시 지킨다.

## 금지

- 전체 프로젝트 파일을 한꺼번에 읽지 않는다.
- 동일 파일을 반복해서 읽지 않는다.
- 이미 확인한 파일을 다시 분석하지 않는다.
- 필요하지 않은 주석을 대량으로 생성하지 않는다.
- 긴 설명을 반복하지 않는다.
- 기존 HTML/JS 코드를 그대로 Godot 코드로 1:1 번역하지 않는다.
- 사용하지 않는 시스템을 미리 구현하지 않는다.
- placeholder 시스템을 수십 개 만들지 않는다.
- 동일한 기능을 여러 방식으로 구현하지 않는다.
- 매 단계마다 전체 프로젝트를 재검사하지 않는다.

## 허용

필요한 파일만 읽는다.

예:

```text
현재 작업 대상:
player
→ player 관련 파일만 확인

현재 작업 대상:
world
→ world 관련 파일만 확인

현재 작업 대상:
UI
→ UI 관련 파일만 확인
```

가능하면 `grep`, 파일 목록, 특정 함수 검색 등을 이용해서 필요한 부분만 확인한다.

# 4. Godot 버전

Godot 4.x 기준으로 작성한다.

프로젝트는 가능한 한 최신 안정적인 Godot 4.x 환경을 기준으로 한다.

렌더링은 모바일을 고려한다.

기본 목표:

```text
Renderer:
Mobile 우선

Target:
Mobile

Target FPS:
60

Fallback:
30 FPS에서도 플레이 가능
```

PC 고사양 게임처럼 무겁게 만들지 않는다.

# 6. 기존 게임의 핵심 재미 유지

기존 saga-forest의 핵심 컨셉을 먼저 파악한다.

기존 게임에 다음과 같은 시스템이 존재한다면 우선 유지한다.

- 플레이어
- 이동
- 맵
- 탐험
- 자연환경
- 동물
- 수집
- 아이템
- 성장
- 퀘스트
- 상호작용
- UI
- 저장

단순히 웹 게임을 3D로 복사하지 않는다.

**기존 게임의 재미를 유지하면서 3D 게임으로 재설계한다.**

---

# 7. 3D 게임 방향

게임의 기본 방향:

## 장르

3D 캐주얼 탐험 / 생활형 어드벤처 / 수집 게임

## 비주얼

현대적인 모바일 3D 스타일.

목표는:

```text
밋밋한 평면 맵
↓
입체적인 숲
```

이다.

---

# 8. 3D 숲 월드

현재 맵이 단순하다면 가장 먼저 개선한다.

숲을 다음처럼 구성한다.

```text
중앙 지역
│
├── 숲
├── 작은 호수
├── 강
├── 언덕
├── 초원
├── 나무 지역
├── 바위 지역
├── 캠프
├── 작은 마을
└── 숨겨진 지역
```

모든 요소를 한꺼번에 구현하지 않는다.

첫 번째 플레이 가능한 맵에서는 다음 정도만 만든다.

```text
중앙 숲
+
작은 호수
+
언덕
+
나무
+
바위
+
풀
+
캠프
```

이것만으로도 공간감이 느껴지게 한다.

---

# 9. 맵 크기

맵은 기존보다 충분히 넓게 만든다.

플레이어가 몇 초 만에 끝까지 도달하는 작은 맵을 만들지 않는다.

다만 무작정 거대한 맵을 만들지 않는다.

목표:

```text
작은 테스트 맵
→
중간 크기 오픈 필드
```

구조로 확장한다.

향후 지역 확장이 가능하도록 설계한다.

---

# 10. 지형

평평한 Plane 하나만 사용하는 것을 금지한다.

다음 요소를 사용한다.

```text
Terrain
Height
Slope
Grass
Rock
Tree
Water
Path
Cliff
```

단, 모바일 성능을 고려하여 지나치게 높은 폴리곤을 사용하지 않는다.

---

# 11. 3D 에셋

가능하면 직접 만든 단순 Primitive만으로 전체 게임을 만들지 않는다.

다음은 실제 3D 에셋 사용을 고려한다.

```text
Player
Animals
Trees
Rocks
Grass
Buildings
Props
Furniture
Plants
```

우선순위:

```text
무료/상업적 사용 가능한 에셋
→
GLB/glTF
→
최적화된 low-poly/stylized 3D
```

Godot에서는 GLB/glTF 2.0을 우선 사용한다.

GLB는 메시와 텍스처를 함께 관리할 수 있어 프로젝트의 에셋 관리에도 적합하다.

에셋을 사용할 경우 반드시 라이선스를 확인한다.

---

# 12. 캐릭터

플레이어는 3D 캐릭터로 구현한다.

기본 기능:

```text
Idle
Walk
Run
Interact
Gather
```

필요하면:

```text
Jump
Attack
Emote
```

를 확장할 수 있도록 구조만 준비한다.

---

# 13. 플레이어 이동

3D 모바일 게임에 적합한 이동을 만든다.

PC:

```text
WASD
Arrow
Mouse
```

모바일:

```text
Virtual Joystick
Touch Button
Camera Drag
```

플레이어 이동은 부드럽게 한다.

급격하게 방향이 바뀌는 방식은 피한다.

---

# 14. 카메라

기본 카메라는 3인칭 카메라를 사용한다.

특징:

```text
Player follow
Smooth movement
Camera rotation
Zoom
Collision avoidance
```

모바일에서는 오른쪽 화면 드래그로 카메라를 회전할 수 있게 한다.

---

# 15. 숲의 생명감

숲이 비어 보이지 않도록 한다.

다음 요소를 추가한다.

```text
새
나비
토끼
사슴
다람쥐
작은 동물
물고기
```

처음부터 모든 동물을 구현하지 않는다.

첫 번째 버전에서는:

```text
토끼
사슴
새
```

정도로 시작한다.

동물은 단순 AI로 구현한다.

```text
Idle
Wander
Flee
Eat
Sleep
```

---

# 16. 자연환경

맵에 다음 요소를 배치한다.

```text
나무
큰 나무
작은 나무
풀
꽃
버섯
돌
바위
나뭇가지
그루터기
연못
폭포
물길
```

중요한 것은 숫자가 아니라 **밀도와 배치**다.

무작위로 마구 배치하지 말고 자연스럽게 보이게 한다.

---

# 17. 환경 연출

단순한 3D 오브젝트 배치에서 끝내지 않는다.

추가:

```text
Directional Light
Environment
Sky
Fog
Ambient Light
Soft Shadows
Water
Particles
```

시간이 충분하면:

```text
Day
Sunset
Night
```

시스템으로 확장한다.

---

# 18. 상호작용

플레이어가 주변 오브젝트에 가까이 가면 상호작용 표시를 한다.

예:

```text
[채집]

[조사]

[줍기]

[대화]

[낚시]
```

모바일에서는 큰 버튼으로 표시한다.

---

# 19. 채집 시스템

숲 게임의 핵심 콘텐츠로 채집을 만든다.

예:

```text
나무
→ 나뭇가지

돌
→ 돌

버섯
→ 버섯

꽃
```

# 20. 인벤토리

최소한의 인벤토리 시스템을 구현한다.

```text
Item
Quantity
Category
Icon
```

아이템 데이터는 코드에 하드코딩하지 말고 가능한 경우 데이터 파일로 분리한다.

예:

```text
data/items/
```

---

# 21. 성장 시스템

과도하게 복잡하게 만들지 않는다.

기본:

```text
Level
EXP
Coins
Collection
```

추후 확장 가능하게 한다.

---

# 22. 퀘스트

초기에는 간단한 퀘스트만 구현한다.

예:

```text
나무 열매 3개 수집

호수 방문

```

퀘스트 시스템은 데이터 기반으로 확장 가능하게 한다.

---

# 23. NPC

첫 버전에서는 NPC를 많이 만들지 않는다.

1~2명의 NPC만 구현한다.

NPC:

```text

Talk
Quest
```

대화 UI를 만든다.

---

---

# 25. 모바일 세로 / 가로

반드시 지원한다.

## 세로

```text
Portrait
```

## 가로

```text
Landscape
```

화면 방향에 따라 UI가 자동으로 재배치되도록 한다.

UI를 특정 해상도에 고정하지 않는다.

---

# 26. 모바일 최적화

최우선으로 고려한다.

다음 항목을 관리한다.

```text
Draw Calls
Polygon Count
Texture Size
Shadow
Particles
Physics
AI Update
Object Count
```

필요하면:

```text
LOD
Culling
Visibility
Object Pool
```

을 사용한다.

---

# 27. 에셋 최적화

3D 에셋은 무조건 고폴리곤을 사용하지 않는다.

권장:

```text
Stylized
Low / Mid Poly
Mobile Friendly
```

텍스처도 지나치게 큰 해상도를 사용하지 않는다.

가능하면 공통 텍스처와 머티리얼을 재사용한다.

---

# 28. 반복 오브젝트 최적화

나무, 풀, 바위처럼 반복되는 오브젝트는 개별적으로 수백 개를 무식하게 생성하지 않는다.

가능하면:

```text
MultiMesh
GPU Instancing
```

등을 활용한다.

Godot에서 지원되는 방식 중 프로젝트 규모에 적합한 방법을 선택한다.

---

# 29. 월드 구조

월드는 나중에 확장할 수 있어야 한다.

예:

```text
World
├── Forest
├── Lake
├── Village
├── Mountain
└── SecretArea
```

처음에는 Forest만 구현해도 된다.

나중에 지역을 추가할 수 있는 구조로 만든다.

---

# 31. 사운드

# 33. 기존 웹 프로젝트 처리

기존 HTML/JS 프로젝트를 삭제하지 않는다.

새 Godot 프로젝트를 별도로 구성한다.

예:

```text
saga-forest/
```

기존 웹:

```text
web/
```

Godot:

```text
godot/
```

또는 기존 저장소 구조를 확인한 후 가장 안전한 위치를 선택한다.

기존 프로젝트를 백업할 수 있는 상태를 유지한다.

각 단계 시작 전에 다음 형식으로 짧게 보고한다.

```text

...

...
```

그리고 바로 작업한다.

작업 후:

```text

```

긴 설명을 하지 않는다.

# 41. 최종 작업 명령

먼저 현재 `saga-forest` 웹 프로젝트를 분석한다.

**아직 전체 구현을 시작하지 않는다.**

1. 현재 프로젝트 구조를 최소한으로 확인한다.
2. 핵심 게임 시스템을 파악한다.
3. 기존 게임에서 유지할 기능을 정리한다.
4. Godot 4 프로젝트 구조를 설계한다.
5. 필요한 파일 목록만 만든다.
6. 위 분석 결과를 짧게 출력한다.
7. 이후 단계별로 구현한다.

중요:

**토큰 절약이 최우선이다.**

이미 확인한 파일을 반복해서 읽지 말고, 필요한 코드만 검색하고 수정한다.

목표는 단순한 HTML 게임을 Godot로 번역하는 것이 아니라,

**기존 saga-forest의 게임성을 유지하면서 현대적인 3D 모바일 숲 탐험 게임으로 재구축하는 것**이다.

최종적으로 다음을 만족해야 한다.

```text
Godot 4
+
3D World
+
3D Character
+
3D Forest
+
Animals
+
Gathering
+
Inventory
+
Quest
+
NPC
+
Mobile Touch
+
Portrait
+
Landscape
+
Save
+
Mobile Optimization
```

그리고 모든 개발 과정에서 **토큰 사용량을 최소화하면서 실제 실행 가능한 상태를 유지한다.**
