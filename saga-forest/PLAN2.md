# SAGA FOREST — Unity 3D 전환 및 고퀄리티 리뉴얼 작업 지시서

## 0. 최우선 원칙 — Claude Code 토큰 절약

이 프로젝트에서 가장 중요한 개발 원칙은 **토큰과 작업량을 최대한 절약하면서 실제 결과물의 품질을 높이는 것**이다.

### 반드시 지켜라

1. 기존 코드를 전체적으로 무작정 읽지 않는다.
2. 작업과 직접 관련된 파일만 먼저 조사한다.
3. 파일을 수정하기 전에 프로젝트 구조를 먼저 요약한다.
4. 이미 구현된 기능을 중복 구현하지 않는다.
5. 같은 파일을 여러 번 전체 재작성하지 않는다.
6. 작은 수정은 부분 수정한다.
7. 코드 생성 전에 기존 구조를 재사용할 수 있는지 확인한다.
8. 한 번에 너무 많은 시스템을 구현하지 않는다.
9. 각 단계가 정상 작동하는지 확인한 후 다음 단계로 이동한다.
10. 오류가 발생하면 관련 파일만 확인하고 수정한다.
11. 불필요한 설명과 장황한 출력은 최소화한다.
12. 작업 결과는 짧게 요약한다.
13. 이미 결정된 사항을 다시 질문하지 않는다.
14. 작업 전에 반드시 현재 상태를 확인하고, 확인할 수 없는 부분은 추측해서 대규모 코드를 만들지 않는다.

### Claude Code 응답 형식

각 작업 완료 후 다음 형식으로 짧게 보고한다.

- 완료:
- 수정 파일:
- 테스트:
- 다음 단계:

불필요한 장문의 설명은 하지 않는다.

초기 맵:

- 중앙 마을
- 북쪽 숲
- 동쪽 강
- 서쪽 초원
- 남쪽 캠핑장

처음부터 모든 지역을 구현할 필요는 없다.

# 22. 모바일 성능 최적화

매우 중요하다.

무조건 고사양 그래픽을 사용하는 것이 목표가 아니다.

**모바일에서 보기 좋은 그래픽 + 안정적인 FPS**

가 목표다.

적용:

- LOD
- Occlusion Culling
- GPU Instancing
- Static Batching
- Texture Atlas
- 적절한 Texture 해상도
- 그림자 거리 제한
- Particle 제한
- Object Pooling

화면 밖 NPC/동물은 업데이트 빈도를 낮춘다.

멀리 있는 오브젝트는 LOD를 사용한다.

---

# 23. 모바일 목표

목표:

- 중급 스마트폰에서도 안정적 실행
- 가능하면 60 FPS
- 상황에 따라 30 FPS 안정성 확보

처음부터 최고 품질만 추구하지 않는다.

그래픽 품질 옵션을 제공한다.

- 낮음
- 중간
- 높음

# 31. 절대 하지 말 것

다음 행동을 금지한다.

- 기존 프로젝트 전체 삭제 후 무작정 새로 작성
- 필요 없는 패키지 설치
- 모든 시스템을 한 번에 구현
- 의미 없는 코드 생성
- 같은 코드를 반복 생성
- 과도한 디자인 패턴 적용
- 필요 없는 추상화
- 사용하지 않는 Manager 남발
- 모든 데이터를 MonoBehaviour에 저장
- 모바일 최적화를 마지막에 생각
- Placeholder Cube만으로 최종 그래픽 구성
- 긴 설명만 하고 실제 구현하지 않는 것

# 33. 에셋 사용 원칙

가능하면 검증된 무료/저가 상용 에셋 또는 직접 제작 가능한 에셋을 사용한다.

중요:

- 라이선스 확인
- 모바일 최적화 확인
- Polygon 수 확인
- Texture 크기 확인
- 애니메이션 호환성 확인

실제 에셋을 사용할 수 없는 환경이라면 임시 Placeholder를 사용하되

**최종 게임 구조가 Placeholder에 종속되지 않게 설계한다.**

# 34. 기존 웹 코드의 역할

기존 웹 코드를 Unity에서 그대로 재사용하려고 하지 않는다.

HTML/CSS/JavaScript를 Unity C#으로 1:1 변환하는 방식은 사용하지 않는다.

대신:

기존 웹 게임
→ 기능 분석
→ 게임 규칙 추출
→ 데이터 구조 추출
→ Unity 방식으로 재설계

한다.

---

# 35. 기존 기능 보존

현재 웹 버전의 핵심 기능을 분석한 뒤 Unity 버전에서도 유지한다.

특히:

- 가방
- 주민
- 집
- 편지
- 공사
- 도감
- 기록

은 삭제하지 않는다.

단순 포팅이 아니라 기능을 업그레이드한다.

# 41. Claude Code 작업 방식

이 프로젝트는 장기 프로젝트다.

따라서 매번 전체 프로젝트를 다시 분석하지 않는다.

작업 전에 다음 파일을 우선 확인한다.

- PROJECT_STATUS.md
- TODO.md
- ARCHITECTURE.md

없으면 최소한의 내용으로 생성한다.

### PROJECT_STATUS.md

현재 구현된 기능만 기록한다.

### TODO.md

다음 작업만 기록한다.

### ARCHITECTURE.md

전체 구조를 짧게 기록한다.

매 작업마다 이 3개 파일을 기준으로 현재 상태를 파악한다.

이를 통해 Claude Code가 매번 프로젝트 전체를 다시 읽는 것을 방지하고 **토큰 사용량을 최소화한다.**
