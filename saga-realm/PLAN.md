# saga-realm 전체 리뉴얼 작업 지시서

대상 프로젝트:

https://smh8627-jpg.github.io/swbins/saga-realm/

현재 프로젝트를 기반으로 **saga-realm을 모바일에서 실제 게임처럼 보이고 플레이할 만한 수준으로 전면 리뉴얼**한다.

중요:
- 기존 프로젝트를 처음부터 다시 만들지 않는다.
- 현재 게임의 구조와 기능을 최대한 재사용한다.
- 기존 기능을 무작정 삭제하거나 대규모로 재작성하지 않는다.
- 먼저 현재 코드 구조를 분석한 후 필요한 파일만 수정한다.
- 가장 중요한 목표는 **토큰 사용량 최소화 + 실제 체감 품질 향상**이다.
- 코드가 이미 잘 구현되어 있는 부분은 절대 불필요하게 다시 작성하지 않는다.

## 지향점 갱신 (2026-09-03, 사용자 지시)

**이 판의 궁극적 목표는 삼국지(중국) 안에 갇히지 않고 전세계 영토를 점령하는
것이다.** 지금의 국토 지도(화북 서른 성, 194/200/208년 세 시나리오)는 그
첫 무대일 뿐이다 — 국토 지도가 턴제 고정판으로 끝나지 않고, 병사·부대가
실시간으로 오가며 정복 범위가 계속 넓어지는 **오픈월드형 지도**로 가는 것이
"26-1. 전체지도"·"오픈월드형 3D 삼국지 전략 RPG"(아래 목표 서술)가 향하는
실제 이유다.

**지도는 절차적으로 무한 생성하는 게 아니라 실제 세계 지리를 바탕으로 한다**
— 판타지 맵을 끝없이 늘리는 방식이 아니라, 실제 지구 지도 위에 정복 범위가
넓어지는 구조다. **현재 실제로 다음에 넓힐 목표 지역은 한국**이다(전세계는
궁극적 방향이고, 당장 손댈 다음 구획은 한반도).

**한국 지역은 2026-09-04에 착수해 첫 갈래를 끝냈다** — `data-city.js`에
성 일곱(양평·국내성·낙랑·대방·위례성·금성·김해)을 `LINKS`로 `beiping`부터
이어 붙였다. **주인 없이(`force:null`) 시작해 정복 대상**이다 — `rtk.js`
`setup()`의 새 `seedNeutral()`이 `garrison` 필드(성마다 12000~20000)로
수비병을, `data-force.js`의 새 `KOREA_OFFICERS`(9인, 가명)로 수비 무장을
채운다. **기존 출진(`march`)·전투(`fight`/`marchInteractive`)·점령
(`capture`)·AI(`tryWar`)는 한 줄도 안 건드렸다** — 새 성이 그냥 "성 하나
더"로 편입돼 다 그대로 재사용된다(조사로 확인한 뒤 그렇게 짰다). 2D
지도는 `viewBox`를 `100→125`로 넓혀 동쪽 자리를 텄다(`ui-rtk.js`
`renderMap()` 한 곳), 3D는 지면이 이미 넉넉해 손 안 댔다.

**다음 갈래(부대 이동·"원정" 명령)는 아직 시작 안 했다** — 기존 출진은
인접한 성 하나로만 그 자리에서 붙는 구조를 그대로 두고(방금 만든 개입형
전투가 설 자리를 지키기 위해서다), **내 땅·주인 없는 빈 땅만 거쳐 먼 성
까지 병력을 실시간(여러 달)으로 옮기는 새 상위 명령**으로 얹을 계획이다.
자세한 설계는 세션 인계 메모(`../SAGA-HANDOFF.md`)의 해당 절 참고.

**실시간 전투는 2026-09-03에 좁은 뜻으로 시작했다** — "지금 결과를
실시간처럼 재생"(사용자가 고른 범위, 판정 개입형이 아니다). `war.js`의
`fight()`는 그대로 두고 합별 스냅샷(`frames`)·일기토 합별 승패(`duel.hits`)
만 결과에 얹었고, `battle3d.js`가 그걸 시간차를 두고 순서대로 재생한다
(합마다 무리가 줄고 성벽이 깎이는 게 보인다).

**전투 도중 명령 개입은 같은 날 이어서 끝냈다** — `war.js`의 라운드 루프
몸통을 `stepRound()`로 뽑아내고(`cmd` 가 없으면 예전 `fight()`와 자릿수까지
같은 값이 나온다), `marchInteractive()`가 그 함수를 합마다 끊어 불러 그
사이에 플레이어의 명령(⚔️ 돌격·🛡️ 수비·➡️ 정공법·↩️ 퇴각)을 받는다.
**플레이어가 손수 출진을 누른 그 싸움에서만** 개입할 수 있다 — AI가 치는
싸움·가늠(forecast)·진영의 달마다 재개(`resolveCamp`)는 여전히 `fight()`를
그대로 쓴다("AI 전용 판정 안 만든다" 원칙, 루트 `CLAUDE.md` 참고). 자세한
사정은 `js/war.js`의 `stepRound`·`marchInteractive` 머리말, `js/battle3d.js`의
`beginLive`·`showState` 머리말 참고.

**세계 각국 인물 이름 정책**: 확장되는 지역(한국 등)의 실존/역사 인물은 **모방
(오마주)이지 복제가 아니다** — 완전히 똑같이 겹치면 안 되고, 표시 이름은
가명으로 임의(랜덤) 정한다(루트 `CLAUDE.md` "하지 말 것"의 이름 정책과 같다).

# 1. 최우선 원칙 — Claude Code 토큰 절약

## 반드시 지킬 것

작업 시작 시 프로젝트 전체 파일을 모두 읽지 않는다.

먼저 다음만 확인한다.

1. package.json
2. 진입점 HTML
3. 주요 JS/TS 진입 파일
4. 렌더링/게임 엔진 관련 파일
5. 플레이어/캐릭터 관련 파일
6. 맵/월드 관련 파일
7. UI 관련 파일
8. assets 폴더 구조

그 후 실제 수정이 필요한 파일만 추가로 읽는다.

### 금지

- 모든 파일을 무조건 cat/read 하지 않는다.
- 이미 확인한 파일을 반복해서 읽지 않는다.
- node_modules를 읽지 않는다.
- 빌드 결과물을 분석하지 않는다.
- 기존 코드를 통째로 복사해서 다시 작성하지 않는다.
- 기존 시스템과 관계없는 파일을 수정하지 않는다.
- 같은 기능을 여러 번 구현하지 않는다.
- 작은 수정에 대규모 리팩터링을 하지 않는다.

### 작업 방식

반드시 다음 순서로 진행한다.

ANALYZE
→ PLAN
→ MODIFY
→ TEST
→ FIX

각 단계에서 필요한 파일만 읽는다.

한 번에 모든 기능을 구현하려 하지 말고 다음 우선순위로 진행한다.

1. 그래픽/렌더링 품질
2. 월드/지형지물
3. 캐릭터/몬스터
4. 콘텐츠 다양성
5. 모바일 세로/가로 대응
6. UI/UX
7. 성능 최적화
8. 최종 버그 수정

# 2. 현재 게임의 가장 큰 문제

현재 saga-realm은 전체적으로 다음 문제가 있다.

- 그래픽 품질이 낮아 보인다.
- 화면에 지형지물이 너무 적다.
- 맵이 비어 보인다.
- 단순한 평면 공간처럼 느껴진다.
- 플레이어가 이동해도 볼거리가 부족하다.
- 콘텐츠가 부족하다.
- 모바일에서 게임다운 완성도가 부족하다.
- 세로/가로 화면 대응이 부족하다.
- 캐릭터와 월드가 서로 어울리지 않는다.
- 에셋을 사용한 게임처럼 보이지 않는다.
- 전체적으로 프로토타입 느낌이 강하다.

따라서 단순히 색상이나 CSS만 변경하지 말고 **게임 화면의 밀도와 시각적 완성도를 근본적으로 개선한다.**

# 5. 3D 에셋 사용 방식

현재 프로젝트에서 사용하는 렌더링 기술을 먼저 확인한다.

예:

- Three.js
- Babylon.js
- Phaser
- WebGL
- 기타

현재 엔진을 유지한다.

이미 GLB/GLTF를 사용할 수 있는 구조라면 실제 3D 모델을 로드하는 방향으로 개선한다.

가능하면:

- GLB
- GLTF
- 텍스처
- 애니메이션

을 사용한다.

단, 외부 에셋을 무작정 수백 개 추가해서 번들 크기를 폭발시키지 않는다.

---

# 6. 에셋 최적화

에셋 개수보다 **재사용성**을 중요하게 생각한다.

예:

나무 하나를 20개 복사해서 사용하되

- scale 변경
- rotation 변경
- 위치 변경

으로 자연스럽게 보이도록 한다.

같은 바위도 여러 크기로 사용한다.

같은 건물도 색상/스케일/배치로 다양하게 보이도록 한다.

가능하면 Instancing 또는 공유 Geometry/Material을 사용한다.

- 계곡

단, 복잡한 지형 시스템을 새로 만드는 것보다 현재 엔진에서 가장 가볍게 구현할 수 있는 방식을 선택한다.

# 9. 화면의 빈 공간을 줄인다

플레이어 주변 일정 반경에는 적절한 밀도의 오브젝트가 항상 존재하도록 한다.

하지만 모든 공간을 오브젝트로 채우지는 않는다.

목표:

"비어 있는 공간"과 "볼거리"의 균형.

예:

길 주변:

나무 → 돌 → 풀 → 꽃 → 상자 → 작은 오브젝트

마을:

건물 → NPC → 깃발 → 상자 → 마차 → 장식

전쟁터:

목책 → 깃발 → 병기 → 병사 → 잔해

---

# 10. 살아있는 월드 구현

단순히 오브젝트를 배치하는 것에서 끝내지 않는다.

가능하면 다음을 추가한다.

- NPC 이동
- 동물 이동
- 새/나비 등 작은 움직임
- 깃발 흔들림
- 나무 흔들림
- 물 애니메이션
- 횃불 불꽃
- 먼지 효과
- 환경 파티클

과도한 파티클은 사용하지 않는다.

모바일 성능을 최우선으로 한다.

---

# 11. 캐릭터 그래픽 개선

플레이어가 단순한 도형처럼 보이지 않도록 한다.

가능하면 실제 캐릭터 모델을 사용한다.

캐릭터에 다음 상태를 지원한다.

- Idle
- Walk
- Run
- Attack
- Hit
- Death

GLB에 애니메이션이 포함되어 있다면 AnimationMixer 등을 이용해 연결한다.

이미 애니메이션 시스템이 있다면 기존 시스템을 최대한 재사용한다.

# 13. 콘텐츠 다양성 추가

현재 게임이 단순히:

이동 → 전투

만 반복되지 않도록 한다.

가능하면 다음 콘텐츠를 추가한다.

# 26-1. 전체지도 — M키식 토글 (2026-09-01 설계, 2026-09-02 구현)

사가블로(`../saga-dungeon/PLAN.md` 28-1절)에 "마을에서 나가 다른 마을/지역으로
간다"는 오버월드 방향을 적어 두면서, 사용자가 다른 네 판에도 남겨 두라고 했다.
이 판(삼국지식 경영·전략)은 **이미 그 구조 자체가 게임의 본체다** — 국토·성·
전황·진(陣)이 전부 3D 국토 지도 위에 있고(Phase 1·6·7·8, 2026-09-01 확인
완료), 여러 성을 오가는 게 원래부터 핵심 플레이다. 새로 만들 "다른 지역"은 없다.

**확인 결과 (2026-09-02):** 이 판은 다른 네 판과 구조가 다르다 — 성안(🏯 시트)·
무장·진영·외교·학당·기록·전투 결과(encounter 카드)가 전부 화면 전환이 아니라
**국토 지도(`#realm`/`#realm3d`) 위에 얹히는 오버레이**다(`js/ui-rtk.js`
`openSheet`/`showBattle`). 즉 국토 지도는 한 번도 실제로 가려 없어지지 않고
늘 밑에 깔려 있다 — 그래서 "성안·전황에서 국토지도로 못 돌아간다"는 문제 자체가
없었다. 다만 그걸 닫는 방법이 ✕ 버튼(또는 시트 바깥 탭)뿐이고 **단축키가
없었다.**

그래서 추가한 것:

- **M 키** — 열린 시트(성안·무장·진영·외교·학당·기록)를 닫아 국토 지도를
  드러낸다(`js/ui-rtk.js` keydown 핸들러, Escape 바로 옆). `Escape`와 같은
  규칙으로 encounter(전투 결과·시나리오/세력 선택처럼 응답을 기다리는 카드)가
  떠 있을 때는 손대지 않는다 — 진행 중인 흐름을 실수로 건너뛰지 않기 위해서다.
  'm' 키는 이 판 어디에서도 안 쓰이고 있어 충돌 없음(확인 완료).
- **🗺️ 버튼** — 시트 머리글(`sheet-head`)의 ✕ 옆에 새로 둠(`id="sheet-map"`,
  title="국토 지도로 (M)"). 모바일에서 키보드가 없어도 같은 동작을 누를 수
  있다. 동작은 ✕와 같은 `closeSheet()`.
- `btn-3d`(🧊, 2D/3D 국토 지도 전환)는 그대로 둔다 — 이번 것과는 다른 기능이다.

# 27. 성능 최적화

모바일에서 가장 중요하다.

목표:

가능하면 30~60 FPS를 유지한다.

다음 최적화를 적극적으로 적용한다.

- frustum culling
- object reuse
- instancing
- shared geometry
- shared material
- texture 압축
- 적절한 texture resolution
- 필요하지 않은 오브젝트 업데이트 중지
- 멀리 있는 NPC AI 업데이트 빈도 감소
- 파티클 제한
- 그림자 품질 제한
- 오브젝트 pooling

# 41. 토큰 절약 규칙

매우 중요.

Claude Code는 다음을 반드시 지킨다.

### 1

프로젝트 전체를 매번 다시 분석하지 않는다.

### 2

수정 전 필요한 부분만 읽는다.

### 3

수정하지 않는 파일의 전체 내용을 출력하지 않는다.

### 4

코드를 수정한 후 전체 파일을 다시 출력하지 않는다.

### 5

변경된 부분만 검증한다.

### 6

작업 완료 후 장황한 설명을 하지 않는다.

### 7

각 단계가 완료되면 짧게:

- 변경 파일
- 핵심 변경
- 테스트 결과

만 보고한다.

### 8

이미 구현된 기능을 발견하면 재구현하지 않는다.

### 9

새로운 라이브러리 설치는 반드시 필요한 경우에만 한다.

### 10

새로운 라이브러리를 설치하기 전에 기존 프로젝트에서 해결할 수 있는지 먼저 확인한다.

### 11

대규모 리팩터링 금지.

### 12

한 번에 최대한 적은 파일을 수정한다.

### 13

같은 파일을 여러 번 전체 수정하지 말고 한 번에 필요한 변경을 묶어서 적용한다.

# 46. 가장 중요한 최종 지시

현재 saga-realm의 장점을 유지하면서 부족한 부분만 집중적으로 개선한다.

**"코드를 많이 작성하는 것"이 목표가 아니다.**

**"최소한의 코드 변경으로 최대한 큰 게임 품질 향상"이 목표다.**

따라서 Claude Code가 작업 중 기존 코드를 보고 이미 구현되어 있는 시스템을 발견하면 반드시 재사용한다.

새 시스템을 만들기 전에 항상:

> "현재 코드에서 재사용할 수 있는가?"

를 먼저 판단한다.

그리고 에셋을 추가할 때도:

> "이 에셋 하나로 여러 장소에서 재사용할 수 있는가?"

를 먼저 판단한다.

최종 결과는 **가볍게 동작하면서도 화면은 풍부하고, 모바일에서 실제 RPG처럼 느껴지는 saga-realm​**을 목표로 한다.

# 부록 · 코드로 그리지 말고 에셋으로 (다섯 판 공통 방침)

**사용자 지시 (2026-08-28). 다섯 판에 다 같이 적용한다.**

> "스크립트로 쓰고 있는 것들은 다 에셋으로 변경 했으면 해."
> "스크립트는 오직 이벤트나 기능들."
> "도감 일러스트나 캐릭터들도 에셋이 없는지 확인해주고 추가해줘. UI 도."

즉 **코드가 도형·그림을 조립해 만들던 것은 전부 실제 에셋으로 갈아 끼운다.**
3D 모델만이 아니다 — **도감 일러스트 · 인물 초상 · UI 그림**까지 포함한다.
남는 스크립트는 **이벤트와 기능(판정 · 규칙 · 상태)** 뿐이다.

## 왜

사용자가 먼저 고른 것이 **품질**이다. "스크립트로 그려서 퀄리티가 떨어진다 —
에셋을 써라" 가 이 축의 시작이었고, 받을 수 있는 CC0 에셋이 이 판의 결
(한옥 · 갓 · 도포)과 다르다는 것을 알고도 **"둘 다 얹는다(품질 우선)"** 를 골랐다.
그러니 **"결이 안 맞아서" 는 안 하는 이유가 되지 못한다.**

## 어떻게

- 새 작업을 잡을 때 **그 판에서 아직 코드가 그리는 것부터 센다.**
  3D 소품 · 건물 · 인물뿐 아니라 **캔버스로 그리는 초상 · 카드 · 아이콘**까지
- **되돌림 길은 지우지 말고 손잡이로 남긴다.** 에셋을 못 받는 자리가 실제로 있다 —
  `file://` 단독판 · 낮은 품질 등급 · 오프라인. 그때는 조용히 옛 그림으로 돌아간다
- **에셋을 못 구하면 그 사실을 알린다.** 이 망은 GitHub(`raw.githubusercontent.com` ·
  `api.github.com`)만 열려서 미러에 없는 것은 못 받는다. CC0 로 존재하지 않는 것
  (예: 특정 인물 일흔의 초상)은 **"안 한다" 가 아니라 "이래서 막혔고 대신 이것을
  할 수 있다"** 로 보고한다 — 사용자가 직접 받아다 줄 수도 있다
- 출처와 라이선스는 판마다 `assets/ASSET_LICENSES.md` 에 적는다.
  **공개 저장소라 재배포가 안 되는 것은 애초에 받지 않는다.**
  저작자 표시가 필수인 것(CC-BY)은 표시 문구를 같이 옮긴다
- **원작사의 실제 에셋은 넣지 않는다.** 이 규칙은 그대로다
