# SAGA-GO 대규모 리뉴얼 작업 지시서

대상 프로젝트:

https://smh8627-jpg.github.io/swbins/saga-go/

## 최우선 목표

현재 `saga-go`를 완전히 새로 만드는 것이 아니다.

**현재 구현되어 있는 기능과 코드 구조를 최대한 보존하면서 그래픽, 월드, 지형지물, 콘텐츠, UX, 모바일 대응을 단계적으로 업그레이드한다.**

가장 중요한 우선순위는 다음과 같다.

1. 토큰 사용량 최소화
2. 현재 코드 구조 분석 후 필요한 부분만 수정
3. 기존 기능 파괴 금지
4. 실제 3D 에셋 기반 그래픽으로 전환
5. 월드를 넓고 풍부하게 만들기
6. 지형지물과 탐험 요소 대폭 추가
7. 반복 플레이가 가능한 콘텐츠 추가
8. 모바일 세로/가로 모드 모두 지원
9. 저사양 모바일에서도 안정적인 FPS 유지
10. 전체적인 게임 완성도를 현재보다 크게 향상

---

# 1. 절대적인 개발 원칙 — 토큰 절약 최우선

Claude Code 작업에서 가장 중요한 것은 **불필요한 파일 전체 분석과 전체 재작성 방지**다.

## 반드시 지켜라

### 1-1. 작업 전에 전체 프로젝트를 무조건 읽지 않는다

먼저 프로젝트 구조만 확인한다.

다음 순서로 진행한다.

1. package.json 확인
2. src 또는 실제 핵심 소스 디렉터리 확인
3. entry 파일 확인
4. 게임 렌더링 핵심 파일 확인
5. UI 관련 핵심 파일 확인
6. asset 관련 디렉터리 확인
7. 실제 수정에 필요한 파일만 읽는다.

필요하지 않은 파일은 읽지 않는다.

---

## 1-2. 매 작업마다 전체 코드를 다시 분석하지 않는다

한 번 분석한 구조는 기억하고 재사용한다.

예:

- renderer 구조 확인
- scene 구조 확인
- player 구조 확인
- map 구조 확인

이후 작업에서는 해당 파일 전체를 다시 읽지 말고 필요한 함수/부분만 확인한다.

---

## 1-3. 작은 수정에 전체 파일을 재작성하지 않는다

금지:

- 기존 파일 전체 삭제
- 기존 시스템 전체 재작성
- 필요 없는 리팩토링
- 모든 컴포넌트 구조 변경
- 사용하지 않는 라이브러리 대규모 추가

허용:

- 필요한 함수 추가
- 기존 함수 수정
- 필요한 컴포넌트 추가
- 필요한 asset loader 추가
- 기존 데이터 구조 확장

---

## 1-4. 작업은 단계별로 진행한다

한 번에 모든 기능을 만들려고 하지 않는다.

다음 순서로 작업한다.

PHASE 0
현재 구조 분석

PHASE 1
3D 에셋 시스템

PHASE 2
월드/지형지물

PHASE 3
탐험 콘텐츠

PHASE 4
전투/이벤트 콘텐츠

PHASE 5
NPC/마을/상호작용

PHASE 6
모바일 세로/가로 대응

PHASE 7
성능 최적화

PHASE 8
최종 UI/UX 및 폴리싱

각 단계 완료 후 오류를 확인하고 다음 단계로 이동한다.

# 3. 현재 가장 큰 문제

현재 게임의 가장 큰 문제는 다음이다.

## 문제 1

월드가 너무 단순하다.

## 문제 2

지형지물이 부족하다.

## 문제 3

플레이어가 이동해도 "구경할 것"이 부족하다.

## 문제 4

현재 그래픽이 프로토타입 수준으로 보인다.

## 문제 5

실제 게임용 3D 에셋이 부족하다.

## 문제 6

콘텐츠가 적어서 반복 플레이 시 금방 지루해질 가능성이 높다.

## 문제 7

모바일 세로/가로 화면을 모두 고려한 레이아웃이 필요하다.

따라서 단순히 색상이나 UI를 바꾸는 수준의 작업은 하지 않는다.

**게임 세계 자체를 풍부하게 만드는 것이 핵심이다.**

# 7. 에셋 품질 방향

현대 모바일 RPG 느낌을 목표로 한다.

단, 고사양 PC MMORPG 수준으로 무작정 폴리곤을 올리지 않는다.

목표:

- stylized realistic
- clean PBR
- 적당한 polygon
- 모바일 친화적
- 일관된 art style
- 동일한 광원 환경
- 동일한 스케일

서로 다른 스타일의 에셋을 마구 섞지 않는다.

---

# 8. 에셋 라이선스

외부 에셋을 사용할 경우 반드시 라이선스를 확인한다.

가능하면:

- CC0
- 상업적 이용 허용
- 재배포 조건이 명확한 에셋

을 우선 사용한다.

라이선스가 불분명한 에셋은 사용하지 않는다.

프로젝트 안에 가능하면:

ASSET_LICENSES.md

를 만들어 사용한 에셋 출처와 라이선스를 기록한다.

---

# 9. GLB 로더 시스템

에셋마다 별도의 로딩 코드를 작성하지 않는다.

공통 AssetManager를 만든다.

예:

AssetManager.loadModel(path)

AssetManager.cloneModel(key)

AssetManager.preload(keys)

AssetManager.clearUnused()

등의 구조를 사용한다.

---

# 10. 에셋 캐싱

같은 나무 100개를 배치한다고 해서 GLB를 100번 로딩하면 안 된다.

한 번 로딩한 모델을 캐싱한다.

그리고 clone 또는 InstancedMesh를 사용한다.

예:

tree.glb

1회 로딩

↓

100개 배치

# 38. 그림자 최적화

환경 오브젝트는 필요하면 baked 또는 간단한 shadow 사용.

를 활용한다.

4K 텍스처를 모바일에 무분별하게 사용하지 않는다.

# 40. 로딩 최적화

- 플레이어
- 기본 맵

먼저 로딩.

이후 지역 진입 시 필요한 에셋을 lazy loading한다.

# 58. 중요한 디자인 방향

게임을 단순히 "3D로 보이게" 만드는 것이 목적이 아니다.

핵심은:

**3D 월드 안에서 플레이어가 계속 새로운 것을 발견하게 만드는 것**

이다.

따라서 다음 질문을 항상 기준으로 삼는다.

"플레이어가 10초 더 걸어갔을 때 새로운 것이 보이는가?"

"30초 더 이동했을 때 새로운 장소가 나오는가?"

"1분 탐험했을 때 새로운 이벤트가 발생할 수 있는가?"

"다시 플레이해도 다른 것을 발견할 가능성이 있는가?"

YES가 되도록 월드를 설계한다.

# 62. 가장 중요한 지시

**한 번에 모든 코드를 작성하지 마라.**

먼저 현재 코드를 분석하고 최소한의 파일만 읽는다.

그 다음 PHASE 1부터 작업한다.

각 단계가 끝나면:

- 변경 파일
- 변경 내용
- 테스트 결과
- 남은 문제

만 간단히 보고하고 다음 단계로 진행한다.

불필요하게 같은 코드를 반복해서 읽지 않는다.

불필요한 설명을 길게 출력하지 않는다.

토큰 절약을 최우선으로 한다.
