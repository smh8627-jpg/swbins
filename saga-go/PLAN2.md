# SAGA-GO Unity 6 리뉴얼 프로젝트

## 최우선 원칙

기존 웹 버전 SAGA-GO를 단순 포팅하지 않는다.

현재 게임의 핵심 게임성은 참고하되,
최종 목표는 Unity 6 기반의 고품질 3D 모바일 게임으로 재구축하는 것이다.

### 매우 중요: 토큰 절약

Claude Code의 토큰 사용량을 최대한 줄여라.

다음 원칙을 반드시 지켜라.

1. 작업 전에 현재 프로젝트 구조를 먼저 분석한다.
2. 전체 파일을 불필요하게 읽지 않는다.
3. 필요한 파일만 검색한다.
4. 이미 작성된 코드를 다시 전체 출력하지 않는다.
5. 변경이 필요한 파일만 수정한다.
6. 동일한 기능을 중복 구현하지 않는다.
7. 기존 시스템을 재사용할 수 있으면 재사용한다.
8. 대규모 리팩터링은 반드시 필요한 경우에만 한다.
9. 작업마다 먼저 변경 대상 파일 목록을 확정한다.
10. 한 번에 전체 게임을 구현하지 않는다.
11. 각 단계가 완료되면 빌드/실행 검증 후 다음 단계로 진행한다.
12. 문제가 없는 기존 코드는 건드리지 않는다.
13. 긴 설명이나 코드를 불필요하게 출력하지 않는다.
14. 작업 결과는 변경 파일, 핵심 변경 내용, 검증 결과만 간단히 보고한다.

# 4. 렌더링

Unity 6 + URP를 사용한다.

목표:

- 고품질 3D
- 모바일 최적화
- 적절한 그림자
- 환경 조명
- 반사
- 파티클
- VFX
- 후처리
- 카메라 연출

단, 그래픽 효과를 무조건 많이 사용하는 것이 목적이 아니다.

"모바일에서 고품질로 보이는 것"이 목표다.

필요하지 않은 HDR, Depth Texture, Opaque Texture,
고비용 Post Processing 등을 무조건 활성화하지 않는다.

성능 측정 후 필요한 기능만 활성화한다.

# 14. 에셋 관리

대규모 에셋을 고려하여 Addressables 사용을 검토한다.

필요한 에셋만 로드하고
사용하지 않는 에셋은 메모리에 계속 유지하지 않는다.

특히 모바일에서:

- 텍스처 크기
- 압축
- Mesh
- Material
- Animation
- Audio

메모리를 관리한다.

---

# 15. 모바일 최적화

처음부터 최적화를 고려한다.

목표:

- 안정적인 60 FPS 우선
- 저사양 기기에서는 30 FPS fallback
- 적절한 LOD
- Occlusion Culling
- GPU Instancing
- SRP Batcher
- 텍스처 압축
- 오브젝트 풀링
- 불필요한 Update 제거
- 불필요한 GC Allocation 제거

풀 한 포대의 풀 오브젝트를
각각 독립 GameObject로 무작정 생성하지 않는다.

반복 오브젝트는 가능한 한 효율적으로 배치한다.

# 19. Claude Code 작업 방식

매 단계마다 반드시 다음 순서로 작업한다.

1. 현재 상태 확인
2. 필요한 파일만 검색
3. 변경 대상 파일 목록 작성
4. 최소 수정
5. 코드 구현
6. 컴파일 오류 확인
7. 실행/테스트
8. 문제 수정
9. 변경사항 요약

절대로 다음 단계까지 한꺼번에 구현하지 않는다.

# 중요

그래픽 품질이 낮은 프로토타입을 빠르게 많이 만드는 것이 목표가 아니다.

적은 양이라도

"실제 모바일 3D RPG처럼 보이는 품질"

을 우선한다.

특히 기본 Cube / Sphere / Capsule / 단순 색상 Plane으로 게임을 채우지 않는다.

실제 3D 에셋과 조명, 지형, 환경 오브젝트를 사용하여
게임 화면 자체가 풍부하게 보이도록 한다.

단, 에셋을 많이 넣는 것이 품질이라는 의미는 아니다.

재사용 가능한 고품질 에셋을 중심으로
성능과 메모리를 함께 관리한다.

# 최종 목표

SAGA-GO를

"웹에서 만든 3D 데모"

가 아니라

"Unity로 제작한 실제 모바일 3D RPG"

수준으로 발전시키는 것이 최종 목표다.

기존 게임의 문제를 그대로 복사하지 말고
Unity의 장점을 이용하여 구조부터 개선한다.
