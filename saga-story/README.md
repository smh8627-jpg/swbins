# 사가스토리 (saga-story)

> 시리즈 전체 인계(다섯 게임 표·지시 이력·함정·다음 할 일)는 **`../SAGA-HANDOFF.md`** 다.

**메이플스토리식 2D 사이드스크롤.** 뛰고, 썰고, 오른다.

**장기 지향점**: 맵과 맵 사이 로딩 없이 걸어서 이어지는 오픈월드 사이드스크롤을
목표로 한다.

```
run.bat          →  http://127.0.0.1:8794
start_server.bat →  같은 것, 브라우저를 열지 않는다 (허브 워치독용)
_test.html       →  자가진단 79항목
_demo.html       →  스크린샷용 데모 상태 (#boss · #hunt · #camp · #field · #dex · #log)
```

## 앞으로 — 3D 로 옮긴다 (`PLAN.md`)

이 폴더의 **`PLAN.md`** 가 앞으로의 방향이다. 이 README 의 나머지는 **지금까지 만든 것**이니,
손대기 전에 둘을 같이 본다.

가는 곳은 **3D 횡스크롤 액션 RPG** 다. 2D 를 3D 로 갈아 끼우는 것이 아니라, 옆으로 걷는
놀이에 **공간의 깊이**를 넣는 쪽이다 — Background / Midground / Foreground 레이어와,
실제로 놀이가 되는 Gameplay Depth.

**Phase 1~6** 으로 잘라 간다 — 현재 분석·3D 기반 → 몬스터·기본 공격 → 스킬·콤보 →
맵 확장·플랫폼 → 성장(레벨) → 콘텐츠(NPC).

계획 맨 앞에 **토큰 절약**이 규칙으로 박혀 있다 — 파일을 통째로 읽지 말고 필요한 곳만
찾아 읽기, 고친 곳만 짧게 보고하기. 큰 작업이라 그렇다.

세이브도 완전히 분리돼 있어 도감·성장이 서로 오가지 않는다.

## 가입해서 저장 (account.js)

첫 실행 때 **이름**을 물어보고, 그 이름으로 진행이 저장된다. 서버는 없다 —
이 브라우저 안에서만 도는 가입이고 비밀번호도 없다.

```
세이브 키   <게임>/save/<프로필id>      ← account.js 가 정해 준다
프로필 목록 <게임>/save/accounts
옛 세이브   <게임>/save/v1             ← 첫 가입 때 '이어받기' 로 옮긴다
```

- 게임 코드는 `game.js` 의 `boot()` 에서 **`DG.account.gate(start)`** 한 줄만 부른다.
  gate 가 프로필을 정해 `core.setSaveKey()` 를 부른 뒤 게임을 켠다
- 상단 **👤** 는 account.js 가 직접 끼워 넣는다 (index.html 을 고칠 필요가 없다).
  이름 바꾸기 · 다른 이름으로 새 판 · 삭제
- 이름은 **게임마다 따로**다 (다섯 프로젝트가 별개이므로)
- 자가진단은 `window.DG_NO_ACCOUNT = true` 로 가입 화면을 건너뛰고 `…/save/test` 를 쓴다

## 자가진단

```
chrome --headless=new --disable-gpu --virtual-time-budget=45000 --dump-dom   http://127.0.0.1:PORT/_test.html        → RESULT n/n
```

**무작위는 씨앗으로 고정돼 있다.** `_test.html` 이 게임 스크립트를 불러오기 **전에**
`Math.random` 을 mulberry32(씨앗 20260824)로 갈아 둔다. 그래서 자동 순행을 몇 분치
굴려 보는 항목도 **매번 같은 수치**가 나온다 — 전에는 그 항목들이 드물게 실패했다
(같은 코드로 24/25 → 25/25). 게임 코드는 손대지 않았으니 실제 플레이는 그대로 무작위다.

세 번 돌려 결과가 **한 줄도 다르지 않은지**로 확인한다. 시각 기반 값(프로필 id 등)은
결과 문구에 넣지 않는다 — 넣으면 매번 달라져서 "무엇이 바뀌었나" 를 눈으로 못 쫓는다.

**어드민은 따로 본다.** 눌러야 도는 화면이라 `_test.html` 이 붙지 못한다:

```
chrome --headless=new --disable-gpu --dump-dom "http://127.0.0.1:PORT/_admin.html?selftest"   → ADMIN n/n
```

**소리가 실제로 나는지도 따로 본다.** 진단은 아무것도 누르지 않아 브라우저가 소리를
늘 잠가 두기 때문이다(그 규칙이 맞다). `_sfxcheck.html` 이 `unlock()` 을 스스로 부른다:

```
chrome --headless=new --disable-gpu --dump-dom http://127.0.0.1:PORT/_sfxcheck.html   → SFX unlock=true · 낸 소리 n/n
```

## 손볼 때

- `core.hash2` 는 **부호 없는 시프트**로 고쳐 뒀다(옛 식은 0~0.5 만 돌려줘서, 문턱값을
  0.9 로 잡으면 아무 것도 생기지 않았다). `deungyong-go` 에는 아직 옛 식이 남아 있다
- 파일을 늘리거나 고쳤으면 **`sw.js` 의 VERSION 도 같이 올릴 것.** 안 올리면 브라우저가
  옛 파일을 물고 있어 한 화면에 세대가 섞인다(그래서 실제로 죽은 적 있다)
- 자동 설정(`save.auto`)은 `auto.js` 의 `st()` 가 **빠진 칸을 채워 준다**
- 헤드리스 크롬(`--screenshot`/`--dump-dom`)에서는 `requestAnimationFrame` 이 거의 돌지
  않는다. 움직임은 스크린샷으로 판정할 수 없으니 `_test.html` 처럼 `update(dt)` 를
  직접 굴려서 본다

## 원작처럼 보이게 (2026-08-26)

**규칙은 한 줄도 안 건드렸다.** 외피는 새 파일 `css/maple.css` 한 장이고,
`index.html` 에서 그 `<link>` 한 줄을 빼면 예전 모습으로 돌아온다
(사가블로의 `css/diablo.css` 와 같은 방식이다).

옮긴 것 여섯 —
**밝은 창**(어두운 유리 → 흰 종이 + 굵은 남색 테) ·
**볼록한 단추** · **체력 빨강 · 기력 파랑 두 줄** ·
**미니맵**(왼쪽 위 밝은 창) ·
**뒷배경**(하늘 맵은 둥근 언덕 두 겹 + 구름 · 숲은 둥근 나무 두 겹 · 굴은 종유석) ·
**데미지 숫자**(굵고 크게, 검은 테를 둘러 위로 튄다. 100 이 넘으면 더 크고 금빛).

`sprite.js` 에는 **넷째 양식 `maple` 을 넣고 기본값으로 삼았다**(📗 단추가 넷을 돈다).
그림책풍(`storyize`)과 **같은 픽셀 훑기를 값만 달리 쓴다** — 채도를 올리고, 색을
넓은 계단으로 눕히고, 실루엣을 진하게 두른다. 작은 그림에는 안쪽 선을 긋지 않는다
(그으면 형태가 선에 먹혀 검은 덩어리가 된다).
넥슨의 실제 에셋은 쓰지 않는다 — **그림 문법만** 옮기고 그림은 이 저장소의 코드가 그린다.

## 이 게임만의 것

- **내 몸은 앞에 세운 인물** — 그 인물의 능력치가 체력·공격력이 된다(`side.power`).
  도감에서 다른 인물을 앞에 세우거나 승급하면 세진다
- **물리** — 중력 1900 · 점프 760 · 달리기 270. 발판은 **위에서만** 밟힌다
  (아래에서 올라갈 때는 통과한다 — 사이드스크롤의 기본 감각)
- **줄과 문** — 밧줄·사다리는 **↑↓ 로 오르내리고**(줄 위에서 Space 는 손 떼기),
  ↓+Space 로 밟고 선 발판을 빠져나간다. 사냥터 끝의 **문 앞에서 ↑** 를 누르면
  옆 사냥터로 걸어 넘어간다 — 체력·기력·주운 금은 그대로 이어진다.
  좌표는 `data-side.js` 의 `ropes`(`[x, 위, 아래, 종류]`) · `portals`(`[x, 갈 곳]`)
- **직업과 무예** — 처음엔 **무명**(연참·횡소·기탄·기합 넷 고정).
  **Lv.10 에 1차 전직**(무사·궁수·협객·방사), **Lv.25 에 2차**(장군·신궁·자객·도사),
  **Lv.45 에 3차**(원수·비장·귀영·진인 — 2026-08-26).
  되돌릴 수 없다. 윗자리로 오르려면 **아랫자리 무예 하나를** 2차는 5, **3차는 8** 이상
  익혀야 한다. **갈래는 넷 그대로**다 — 다섯으로 늘리면 인물 능력치와 무기가 따라가야 한다.
  대신 각 갈래를 한 단 더 높였다. 직업 **13** · 무예 **48**
- **무예 점수(SP)** — 레벨마다 3점. **세이브에 담지 않는다** — 총점 (레벨-1)×3 에서
  찍은 레벨의 합을 뺀 것이 남은 점수다(파생값이라 옛 세이브에도 그냥 맞는다).
  **찍은 무예만 조작 띠(1~8)에 놓인다** — 원작 그대로.
  띠는 여덟 칸이고 **윗자리 무예부터** 놓는다(3차까지 열리면 한 갈래가 열둘이라
  아래에서부터 채우면 새로 얻은 무예가 영영 자리를 못 잡는다)
- **무예의 효과 아홉** — `melee`(앞) · `aoe`(주위) · `bolt`(관통) · `arrow`(첫 하나) ·
  `volley`(여러 발) · `dash`(밀고 나가며) · `rain`(앞쪽에 쏟기) · `buff` · `heal`.
  데이터(`data-job.js`)는 무엇을 할지만 적고 **어떻게 하는지는 `side.js` 에만** 있다.
  **3차 스물을 넣으며 효과는 하나도 안 늘렸다** — 늘리면 규칙을 두 곳에 적게 된다
  (진단 '무예 마흔여덟은 side.js 가 아는 효과 아홉만 쓴다')
- **사냥터 4곳** — 허창 들판(Lv.1) → 오림 숲(Lv.5) → 한중 굴혈(Lv.12) →
  **호로곡(葫蘆谷)(Lv.25)**. 적은 던전 게임과 같은 `data-enemy.js` 를 쓴다
- **멀리서 쏘는 적** — **든 무기가 곧 사거리다.** 활(`bow`)·조총(`staff`)을 든 적은
  사거리(360·420)에 들면 **멈춰서 쏜다**. `data-enemy.js` 는 던전 게임과 나눠 든 같은
  파일이라 거기에 `ranged` 칸을 만들지 않았다 — 규칙은 `data-side.js` 의 `rangedOf()`
- **장비** — 부위 일곱(무기·투구·갑옷·전군·전화·수갑·망토) × 네 단(Lv.1·5·12·20).
  낀 것이 **인물의 힘 위에 얹힌다**(`side.power()` 가 `gear.bonus()` 를 더한다).
  방어는 맞는 값을 깎되 **6할까지만** 막는다 — 넘게 두면 후반에 아무것도 안 아파진다
- **주문서** — 원작의 그 물건. 100%·60%·10% 셋. **실패해도 물건은 터지지 않고**
  업횟(`left`)만 닳는다. 초기 원작도 그랬다
- **가방 24칸 · 저자(상점)** — 차면 못 줍는다(그 답답함이 규칙이다). 파는 값은 산 값의 3할
- **사명(使命)** — 원작의 퀘스트. 열셋(되받는 것 셋 포함). **받은 뒤부터** 센다.
  장비·무예·금처럼 **보면 아는 것은 세어 두지 않고 그때그때 읽는다** —
  세어 두면 장비를 벗었다 껴도 수가 남아 어긋난다. 사냥터 시트 안에 있다
- **앉아 쉬기** — ↓ 를 누른 채 가만히 있으면 앉아 체력 2%/초 · 기력 5.5%/초를 채운다.
  곁에 적이 오면 일어선다 (원작에서 의자에 앉던 그 자리다)
- **미니맵** — 왼쪽 위. 자리·축척(`sideView.miniBox`)은 **그리기와 떼어 둬** 진단이 붙는다
- **탕약🧪** — Q 로 마신다(체력 45%). 잡을 때 가끔 떨어진다
- **쓰러지면** 그 판에서 주운 금의 **절반만** 남는다 (사냥터는 그대로)
- **자동 사냥(🤖)** — 가까운 적으로 달려가 베고, 적이 한 층 위/아래면 **줄을 타고**,
  체력 35% 밑이면 탕약, 18% 밑이면 나온다. 줄을 쓰게 되면서 5분치 수확이
  **36 → 120마리**로 올랐다. 그 뒤 궁수(**79**)·줄 고르기 좁히기(**46**)를 거쳐
  그 뒤 자동이 띠에 놓인 무예를 **종류대로**(근접/원거리/돌진/북돋움/치유) 쓰게 해
  **97마리**가 되었고(자리 번호로 고르면 전직한 뒤 근접 무예를 멀리서 휘두른다),
  **급소가 들어와 지금은 108마리**다 — 15%×1.6배가 그대로 수확에 얹혔다
  (진단 '자동 — 5분치를 굴리면 실제로 잡힌다')

## 폰에서 하기 (2026-08-26)

폰(390px)에서 실제로 열어 보니 네 군데가 막혀 있었다. **규칙은 한 줄도 안 고쳤다** —
막힌 것은 손이 닿는 자리였다.

- **↓ 가 아예 없었다.** 캔버스를 위/아래좌/아래우 셋으로만 읽어서, 폰에서는
  **줄을 타고 내려갈 수도, 앉아 쉴 수도, 발판을 빠져나갈 수도 없었다** — 규칙은 다
  있는데 손이 닿지 않는 자리였다. 아래쪽 **가운데 22%** 를 ↓ 로 냈다.
  좁게 잡은 것은 걷다가 잘못 눌리지 않게 하려는 것이다

  ```
  ┌─────────────────────┐
  │   위 45%  ↑ / 점프   │   줄·문 앞이면 오르기·들어가기, 아니면 점프
  ├──────┬───────┬──────┤
  │  ←   │   ↓   │  →   │   가운데 22% 가 ↓ 다
  └──────┴───────┴──────┘
  ```

- **누른 채 끌면** 손가락을 따라 방향이 바뀐다(`setPointerCapture` 로 HUD 위를 지나도
  안 끊긴다). 끌어서 위로 올라가는 것은 점프로 읽지 않는다 — 걷다가 뛰어 버린다
- **상단이 무너졌다.** 프로필 이름이 한 글자씩 줄바꿈되고 도구 여섯 중 둘이 화면 밖으로
  나갔다. 560px 아래에서 이름은 한 줄로 자르고 도구는 **넷씩 두 줄**로 접는다
- **조작 띠 여덟 칸이 독에 덮였다**(3차 전직으로 여섯에서 여덟이 되었다).
  폰에서는 **접어서 두 줄**로 두고 독보다 위로 올린다
- **보스 바와 미니맵이 상단 UI 와 한 자리를 다퉜다.** 좁은 폭에서 상단이 두 줄로
  접히므로 미니맵은 196px, 보스 바는 254px 로 내렸다 — 폰에서 **무엇이 달려드는지**를
  못 읽던 자리다
- **폰에 없는 키를 누르라고 안내했다.** `core.touchOnly()`·`actHint()`·`upHint()`·
  `downHint()` 를 두어(사가의숲과 **같은 이름**) 손가락뿐인 기기에서는 누를 자리를 적는다.
  **키보드가 있는 기기는 예전 문구 그대로다** — 그래서 진단 출력도 안 바뀐다

`_mobileframe.html` 이 폰 화면을 보는 껍데기다. **헤드리스 크롬은 창 폭을 500px 아래로
못 내리므로**, iframe 안쪽에 진짜 390px 뷰포트를 만든다(사가의숲과 같은 꼴).

```
chrome --headless=new --disable-gpu --window-size=700,900 \
  --touch-events=enabled --blink-settings=primaryHoverType=1,availableHoverTypes=1,\
primaryPointerType=2,availablePointerTypes=4 \
  --dump-dom "http://127.0.0.1:PORT/_mobileframe.html#probe"        → PROBE OK
```

`#probe` 는 실제로 이벤트를 쏘아 **걷기·점프·내려가기가 듣는지**와 **단추가 화면 안에
있는지**를 함께 본다. `#hunt`·`#gorge`·`#bag` 같은 해시로 그 화면을 찍어 볼 수도 있다.
손가락뿐인 기기 흉내는 위의 `--blink-settings` 가 낸다 — 그것 없이는 헤드리스가
**hover 가 있는 기기**로 잡혀 터치 분기가 안 걸린다.

## 소리 (`js/sfx.js`) — 2026-08-26

에셋을 안 들이고 **WebAudio 로 절차적으로** 낸다 — 그림을 코드가 그리는 것과 같은
규칙이고, 단독 실행판이 파일 하나라는 사정도 있다. 사가블로의 `js/sfx.js` 와 **같은
엔진**이고 소리표만 이 판의 것이다(원작의 결을 따라 높고 맑은 쪽으로 잡았다).
겹은 셋뿐이다 — 미끄러지는 톤 · 걸러 낸 잡음 · 음을 차례로 놓는 것. 그 셋으로 **37가지**.

**이 판이 소리를 들인 까닭의 절반은 주문서다.** 원작에서 주문서를 긁는 순간 화면을
보기 전에 소리로 성패를 안다. 그래서 둘을 아주 다르게 잡았다 — 오르는 화음(`scrollok`)
대 떨어지는 잡음(`scrollno`). 나머지 절반은 **레벨업 팡파레**다.

지킨 선 넷 —
**첫 눌림 전에는 못 낸다**(브라우저 규칙. `sfx.js` 가 스스로 문서에 걸어 두니
**다른 파일은 이 규칙을 몰라도 된다**) ·
**요청은 꺼져 있어도 적는다**(`_tail()`. 판정 층과 소리 층을 가른 것이라 헤드리스
진단이 "이때 이 소리를 냈어야 한다" 를 검사할 수 있다) ·
같은 소리는 최소 간격을 둔다(사냥터에 적이 열이면 타격음이 겹쳐 소음이 된다) ·
AudioContext 는 한 번만 만든다.

- **무예 스물여덟에 소리를 하나씩 두지 않았다** — 귀가 가리는 것은 넷뿐이다.
  `skillCue(effect)` 가 가까이 벤다·멀리 쏜다·몸을 두른다·낫는다로 묶는다
- **몸 소리(점프·착지·줄·앉기)는 가장 작고 짧다** — 사이드스크롤이라 가장 자주 나고,
  크게 잡으면 5분 자동 사냥에 귀가 먼저 지친다
- 이미 있는 이벤트로 되는 것(레벨업·사냥터 들기·문·죽음)은 `sfx.js` 가 스스로 받고,
  프레임마다 나는 것(타격·줍기·점프·줄)은 `side.js` 가 `fx.push` 옆에서 부른다
- 규칙 파일은 `sfx()` 잔손 하나만 안다 — **`sfx.js` 가 없어도 그대로 돈다**
  (데모·진단이 그 자리다)
- 상단 🔊 로 끈다(`settings.sound`). 꺼도 요청은 남는다

## 어드민 (`_admin.html`) — 2026-08-26

사가고·사가의숲의 어드민과 같은 결이고, 손잡이 층(`core.tuned`)도 **같은 이름**이다.
게임을 켜지 않고 세이브와 손잡이만 다룬다 — 그림도 루프도 없는 창이다.
탭 여덟: 세이브 · 사냥터/보스 · 장비/가방 · 직업/무예 · 사명 · 균형 손잡이 ·
QA 프리셋 12 · 점검(자가점검 10항목).

**이 판에서 가장 값진 탭은 '균형 손잡이' 의 물리 셋이다** — 사이드스크롤은 손맛이 곧
게임이라, 중력·점프·달리기를 눌러 두고 게임 창에서 곧바로 뛰어 보는 것이 검증이다.
손잡이 넷 벌(기본·가볍게·묵직하게·빠르게)을 단추로 두었다.

- 손잡이는 **세이브와 다른 칸**에 산다(`yeoksa-side/tune`). 세이브에 섞으면 프로필마다
  규칙이 달라지고, 세이브를 넘길 때 규칙까지 따라간다 — 규칙은 "이 기기의 사정" 이다
- 규칙 값은 모듈이 **켜질 때 한 번** 읽는다. 바꾼 뒤에는 게임 창을 새로고침해야 듣는다
- **자가진단·데모는 손잡이를 읽지 않는다**(`DG_NO_TUNE`) — 진단 83 항목 중 넷이 그 못이다
- 세이브를 고치면 `POKE_KEY` 를 두드린다. 게임 창이 열려 있으면 그것을 보고 다시 읽는다
  (게임이 틈틈이 저장하므로, 안 그러면 어드민이 고친 값이 곧 덮인다)
- **게임에서 되돌릴 수 없는 것을 되돌린다** — 전직이 그렇다. 어드민의 몫은 "그 상황으로
  곧장 가는 것" 이지 규칙을 지키는 것이 아니다. 규칙(`job.canJoin`)은 한 줄도 안 건드렸다
- 사명을 채우는 방법은 **갈래마다 다르다.** 쌓이는 것(적·보스)은 세이브의 수를 올리면
  되지만, 보면 아는 것(장비·무예·금)은 세어 두지 않으므로 **실제로 그 상태를 만든다**
- 어드민은 PC 단독판에도 `sw.js` 캐시에도 안 들어간다(빌드가 `index.html` 만 훑는다)

손잡이 열넷 — `side.grav`·`side.jump`·`side.speed`·`side.climb`·`side.mpRegen` ·
`enemy.hpMul`·`enemy.dmgMul` · `gain.expMul`·`gain.goldMul` ·
`drop.potion`·`drop.gearMul` · `scroll.rateMul` · `boss.coolMul` · `gear.bag`.

  상단 🧊 단추(`btn-3d`)로 켜고 끌 수 있다(사가의숲·사가국지와 같은 자리) — 손잡이
  `sideView3d.on`(기본 켬)을 그 자리에서 뒤집는다. 실기기 확인 완료(잘 나옴).
- **Phase 2 착수** — `js/asset3d.js` 신설. 오림 숲의 나무, 한중 굴혈의 바위,
  허창 들판·호로곡의 먼 언덕이 Quaternius CC0 GLB 로 선다(출처는
  `assets/ASSET_LICENSES.md`). GLB 를 못 받으면(느린 회선·file:// 단독판) 조용히
  이전의 도형(원뿔·구)으로 남는다 — **한 줄도 판정에 닿지 않는다**.
  천장에 매달린 종유석·불타는 골짜기의 불길은 아직 도형/이펙트 그대로다.
- **Phase 2 마무리 — 사람·짐승 GLB.** 주인공·사람 형 적(황건적·산적…)이 몸+옷+머리를
  한 뼈대에 묶는 조합형 GLB(saga-forest·saga-dungeon과 같은 창고)로, 짐승 형 적
  (들개·코끼리병)은 늑대·소 GLB 로 선다. 걷기·맞음·가만있기 몸짓(UAL1 애니메이션)이
  실제로 돈다. GLB 를 못 받으면 조용히 이전의 도형 캡슐로 남는다 — 판정은 그대로.
  피격 번쩍임은 GLB 에선 emissive 물들임으로(옷 색을 곱셈으로 지우지 않는다).
  헤드리스로 들판·오림 숲·굴혈·호로곡 네 사냥터 모두 사람·짐승 GLB 가 실제로
  붙는 것과 콘솔 에러 없음을 확인했다. 실기기 확인 전.
