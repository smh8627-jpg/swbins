## 네 게임 중 하나

사가 시리즈는 2026-08-24 부터 **완전히 별개인 다섯 프로젝트**다.
네 게임은 원작 장르를 그대로 모방하고, 사가경영만 상상으로 만든 판이다.

| 게임 | 폴더 | 포트 | 원작 | 세이브 키 |
|---|---|---|---|---|
| **사가고** | `saga-go` | 8791 | 포켓몬GO | `deungyong-go/save/v1` |
| **사가블로** | `saga-dungeon` | 8792 | 디아블로 | `yeoksa-dungeon/save/v1` |
| **사가의숲** | `saga-forest` | 8793 | 동물의숲 | `yeoksa-village/save/v1` |

**공용 파일은 복사본이다** — `data.js`(인물 48) · `sprite.js` · `core.js` · `hero.js` 가
다섯 프로젝트에 각각 한 벌씩 있다. 문답은 사가경영만 갖는다.
사용자가 그렇게 고른 구조다(완전 독립). **인물을 하나 추가하면 다섯 곳을 고쳐야 한다.**
세이브도 완전히 분리돼 있어 도감·성장이 서로 오가지 않는다.

## 가입해서 저장 (account.js)

첫 실행 때 **이름**을 물어보고, 그 이름으로 진행이 저장된다. 서버는 없다 —
이 브라우저 안에서만 도는 가입이고 비밀번호도 없다.

```
세이브 키   <게임>/save/<프로필id>      ← account.js 가 정해 준다
프로필 목록 <게임>/save/accounts
옛 세이브   <게임>/save/v1             ← 첫 가입 때 '이어받기' 로 옮긴다
```

- 게임 코드는 `game.js` 의 `boot()` 에서 **`DG.account.gate(start)`** 한 줄만 부른다.
  gate 가 프로필을 정해 `core.setSaveKey()` 를 부른 뒤 게임을 켠다
- 상단 **👤** 는 account.js 가 직접 끼워 넣는다 (index.html 을 고칠 필요가 없다).
  이름 바꾸기 · 다른 이름으로 새 판 · 삭제
- 이름은 **게임마다 따로**다 (다섯 프로젝트가 별개이므로)
- 자가진단은 `window.DG_NO_ACCOUNT = true` 로 가입 화면을 건너뛰고 `…/save/test` 를 쓴다

## PC 에서 하기

```
build-pc.bat  →  dist/<게임이름>.html (한 파일) · play.bat · 사용법.txt
```

css·js 를 전부 한 파일에 녹여 넣으므로 서버도 파이썬도 필요 없다. 다섯 판을 한 번에
묶으려면 `tools/saga-pc/build-all.bat` — `saga-pc/dist/` 에 다섯 html + 런처(index.html)가 나온다.

## 자가진단

```
chrome --headless=new --disable-gpu --virtual-time-budget=45000 --dump-dom   http://127.0.0.1:PORT/_test.html        → RESULT n/n
```

**무작위는 씨앗으로 고정돼 있다.** `_test.html` 이 게임 스크립트를 불러오기 **전에**
`Math.random` 을 mulberry32(씨앗 20260824)로 갈아 둔다. 그래서 자동 순행을 몇 분치
굴려 보는 항목도 **매번 같은 수치**가 나온다 — 전에는 그 항목들이 드물게 실패했다
(같은 코드로 24/25 → 25/25). 게임 코드는 손대지 않았으니 실제 플레이는 그대로 무작위다.

세 번 돌려 결과가 **한 줄도 다르지 않은지**로 확인한다. 시각 기반 값(프로필 id 등)은
결과 문구에 넣지 않는다 — 넣으면 매번 달라져서 "무엇이 바뀌었나" 를 눈으로 못 쫓는다.

## 손볼 때

- `core.hash2` 는 **부호 없는 시프트**로 고쳐 뒀다(옛 식은 0~0.5 만 돌려줘서, 문턱값을
  0.9 로 잡으면 아무 것도 생기지 않았다). `deungyong-go` 에는 아직 옛 식이 남아 있다
- 파일을 늘리거나 고쳤으면 **`sw.js` 의 VERSION 도 같이 올릴 것.** 안 올리면 브라우저가
  옛 파일을 물고 있어 한 화면에 세대가 섞인다(그래서 실제로 죽은 적 있다)
- 자동 설정(`save.auto`)은 `auto.js` 의 `st()` 가 **빠진 칸을 채워 준다**
- 헤드리스 크롬(`--screenshot`/`--dump-dom`)에서는 `requestAnimationFrame` 이 거의 돌지
  않는다. 움직임은 스크린샷으로 판정할 수 없으니 `_test.html` 처럼 `update(dt)` 를
  직접 굴려서 본다

## 원작처럼 보이게 (2026-08-26)

**규칙은 한 줄도 안 건드렸다.** 외피는 새 파일 `css/maple.css` 한 장이고,
`index.html` 에서 그 `<link>` 한 줄을 빼면 예전 모습으로 돌아온다
(역사블로의 `css/diablo.css` 와 같은 방식이다).

옮긴 것 여섯 —
**밝은 창**(어두운 유리 → 흰 종이 + 굵은 남색 테) ·
**볼록한 단추** · **체력 빨강 · 기력 파랑 두 줄** ·
**미니맵**(왼쪽 위 밝은 창) ·
**뒷배경**(하늘 맵은 둥근 언덕 두 겹 + 구름 · 숲은 둥근 나무 두 겹 · 굴은 종유석) ·
**데미지 숫자**(굵고 크게, 검은 테를 둘러 위로 튄다. 100 이 넘으면 더 크고 금빛).

`sprite.js` 에는 **넷째 양식 `maple` 을 넣고 기본값으로 삼았다**(📗 단추가 넷을 돈다).
그림책풍(`storyize`)과 **같은 픽셀 훑기를 값만 달리 쓴다** — 채도를 올리고, 색을
넓은 계단으로 눕히고, 실루엣을 진하게 두른다. 작은 그림에는 안쪽 선을 긋지 않는다
(그으면 형태가 선에 먹혀 검은 덩어리가 된다).
넥슨의 실제 에셋은 쓰지 않는다 — **그림 문법만** 옮기고 그림은 이 저장소의 코드가 그린다.

## 이 게임만의 것

- **내 몸은 앞에 세운 인물** — 그 인물의 능력치가 체력·공격력이 된다(`side.power`).
  도감에서 다른 인물을 앞에 세우거나 승급하면 세진다
- **물리** — 중력 1900 · 점프 760 · 달리기 270. 발판은 **위에서만** 밟힌다
  (아래에서 올라갈 때는 통과한다 — 사이드스크롤의 기본 감각)
- **줄과 문** — 밧줄·사다리는 **↑↓ 로 오르내리고**(줄 위에서 Space 는 손 떼기),
  ↓+Space 로 밟고 선 발판을 빠져나간다. 사냥터 끝의 **문 앞에서 ↑** 를 누르면
  옆 사냥터로 걸어 넘어간다 — 체력·기력·주운 금은 그대로 이어진다.
  좌표는 `data-side.js` 의 `ropes`(`[x, 위, 아래, 종류]`) · `portals`(`[x, 갈 곳]`)
- **직업과 무예** — 처음엔 **무명**(연참·횡소·기탄·기합 넷 고정).
  **Lv.10 에 1차 전직**(무사·궁수·협객·방사), **Lv.25 에 2차**(장군·신궁·자객·도사).
  되돌릴 수 없다. 윗자리로 오르려면 **아랫자리 무예 하나를 5 이상** 익혀야 한다
- **무예 점수(SP)** — 레벨마다 3점. **세이브에 담지 않는다** — 총점 (레벨-1)×3 에서
  찍은 레벨의 합을 뺀 것이 남은 점수다(파생값이라 옛 세이브에도 그냥 맞는다).
  **찍은 무예만 조작 띠(1~6)에 놓인다** — 원작 그대로
- **무예의 효과 여덟** — `melee`(앞) · `aoe`(주위) · `bolt`(관통) · `arrow`(첫 하나) ·
  `volley`(여러 발) · `dash`(밀고 나가며) · `rain`(앞쪽에 쏟기) · `buff` · `heal`.
  데이터(`data-job.js`)는 무엇을 할지만 적고 **어떻게 하는지는 `side.js` 에만** 있다
- **사냥터 3곳** — 허창 들판(Lv.1) → 오림 숲(Lv.5) → 한중 굴혈(Lv.12).
  적은 던전 게임과 같은 `data-enemy.js` 를 쓴다
- **멀리서 쏘는 적** — **든 무기가 곧 사거리다.** 활(`bow`)·조총(`staff`)을 든 적은
  사거리(360·420)에 들면 **멈춰서 쏜다**. `data-enemy.js` 는 던전 게임과 나눠 든 같은
  파일이라 거기에 `ranged` 칸을 만들지 않았다 — 규칙은 `data-side.js` 의 `rangedOf()`
- **장비** — 부위 일곱(무기·투구·갑옷·전군·전화·수갑·망토) × 네 단(Lv.1·5·12·20).
  낀 것이 **인물의 힘 위에 얹힌다**(`side.power()` 가 `gear.bonus()` 를 더한다).
  방어는 맞는 값을 깎되 **6할까지만** 막는다 — 넘게 두면 후반에 아무것도 안 아파진다
- **주문서** — 원작의 그 물건. 100%·60%·10% 셋. **실패해도 물건은 터지지 않고**
  업횟(`left`)만 닳는다. 초기 원작도 그랬다
- **가방 24칸 · 저자(상점)** — 차면 못 줍는다(그 답답함이 규칙이다). 파는 값은 산 값의 3할
- **사명(使命)** — 원작의 퀘스트. 열셋(되받는 것 셋 포함). **받은 뒤부터** 센다.
  장비·무예·금처럼 **보면 아는 것은 세어 두지 않고 그때그때 읽는다** —
  세어 두면 장비를 벗었다 껴도 수가 남아 어긋난다. 사냥터 시트 안에 있다
- **앉아 쉬기** — ↓ 를 누른 채 가만히 있으면 앉아 체력 2%/초 · 기력 5.5%/초를 채운다.
  곁에 적이 오면 일어선다 (원작에서 의자에 앉던 그 자리다)
- **미니맵** — 왼쪽 위. 자리·축척(`sideView.miniBox`)은 **그리기와 떼어 둬** 진단이 붙는다
- **탕약🧪** — Q 로 마신다(체력 45%). 잡을 때 가끔 떨어진다
- **쓰러지면** 그 판에서 주운 금의 **절반만** 남는다 (사냥터는 그대로)
- **자동 사냥(🤖)** — 가까운 적으로 달려가 베고, 적이 한 층 위/아래면 **줄을 타고**,
  체력 35% 밑이면 탕약, 18% 밑이면 나온다. 줄을 쓰게 되면서 5분치 수확이
  **36 → 120마리**로 올랐다. 그 뒤 궁수(**79**)·줄 고르기 좁히기(**46**)를 거쳐
  지금은 **97마리**다 — 자동이 띠에 놓인 무예를 **종류대로**(근접/원거리/돌진/북돋움/치유)
  쓰게 한 값이다. 자리 번호로 고르면 전직한 뒤 근접 무예를 멀리서 휘두른다
  (진단 '자동 — 5분치를 굴리면 실제로 잡힌다')

## 파일

```
js/data-side.js   사냥터(발판·줄·문) · 스킬 · 드랍 · 원거리 무기   ← 사냥터 추가는 여기만
js/data-gear.js   장비(부위 7 × 단 4) · 주문서 7            ← 물건 추가는 여기만
js/data-job.js    직업 9 · 무예 28                         ← 무예 추가는 여기만
js/data-quest.js  사명 13                                  ← 사명 추가는 여기만
js/gear.js        장비 규칙 — 줍기·끼기·주문서·저자 매매
js/job.js         직업 규칙 — 전직·무예 점수·조작 띠
js/quest.js       사명 규칙 — 받기·세기·바치기 ('side:kill' 을 듣는다)
js/data-enemy.js  적 (던전 게임과 같은 파일의 복사본)
js/side.js        사냥 규칙 — 물리·공격·적·드랍·탕약 (캔버스를 모른다)
js/side-view.js   사냥터 화면 — 하늘·먼 산·발판·적·연출 (계산하지 않는다)
js/auto.js        자동 사냥
js/ui.js          쉬는 판 · 조작 띠(체력·기력·스킬) · 사냥터 · 도감 · 서당 · 기록
js/game.js        부트 · 루프 · 키보드
```
